# 15. 터미널 명령 모음

> 로컬에서 Wearly를 띄우고 확인하는 명령. 모든 명령은 저장소 루트(`/Users/showzone/Workspace/wearly`) 기준이다. DB·Valkey·MinIO 명령은 [14_DB_명령.md](14_DB_명령.md).

## 1. 한 번에 띄우기 (평소)

```bash
# DB · Valkey · MinIO(옷 사진) · 백엔드 · 관리자 사이트를 새로 빌드해 실행 (로그를 보면서, Ctrl+C로 중지)
docker compose up --build

# 백그라운드로 띄우기
docker compose up -d --build

# 앱 (Mac에서 따로) — 휴대폰은 Expo Go로 QR, 시뮬레이터는 터미널에서 i, 브라우저는 w
cd mobile && npx expo start
```

| 서비스 | 주소 |
|---|---|
| 백엔드 API | http://localhost:8080 (헬스 체크 `/actuator/health`) |
| 관리자 사이트 | http://localhost:5173 (계정은 `backend/config/application-local.yml`의 `wearly.admin`) |
| DB | `localhost:5433` |
| Valkey (로그인 세션, doc/16) | `localhost:6380` (`docker exec -it wearly-valkey valkey-cli`) |
| MinIO (옷 사진, doc/18) | S3 API `localhost:9000`, 웹 콘솔 http://localhost:9001 (로컬 전용 계정 `wearly` / `wearly-minio-local`) |
| 앱 개발 서버 (Metro) | 8081 |

> 코드를 바꾼 뒤에는 `--build`를 붙여야 컨테이너에 새 코드가 들어간다. 빼면 예전 이미지로 뜬다.

## 2. docker compose

```bash
docker compose ps                     # 상태
docker compose logs -f backend        # 백엔드 로그 따라 보기 (admin, db, valkey, minio도 같음)
docker compose restart backend        # 재시작 (이미지는 그대로)
docker compose up -d --build backend  # 백엔드만 다시 빌드해 띄우기
docker compose stop admin             # 관리자 컨테이너만 멈추기 (npm run dev와 5173 포트가 겹칠 때)
docker compose up -d db valkey minio minio-init   # DB·Valkey·사진 저장소만 (백엔드를 Mac에서 bootRun으로 돌릴 때). minio-init은 버킷을 만들고 끝난다
docker compose down                   # 모두 내리기 (DB 데이터·로그인 세션·옷 사진은 볼륨에 남는다)
docker compose down -v                # ⚠️ DB 데이터·로그인 세션·옷 사진까지 지우기
```

## 3. 백엔드 (`backend/`, Spring Boot)

Java 21이 필요하다. 기본 `java`가 다른 버전이면 앞에 `JAVA_HOME`을 붙인다.

```bash
cd backend
export JAVA_HOME=/Users/showzone/Library/Java/JavaVirtualMachines/openjdk-21.0.2/Contents/Home

./gradlew bootRun            # Mac에서 실행 (실제 AI 공급자). 먼저 docker compose stop backend (8080 충돌), DB·Valkey·MinIO(minio-init 포함)는 떠 있어야 한다
./gradlew test               # 테스트 (Testcontainers로 PostgreSQL·Valkey·MinIO를 띄운다. Docker 필요)
./gradlew bootRunMock        # 목업 AI로 실행 (키 없이 개발)
./gradlew check              # 포맷 검사 + Checkstyle + 테스트 (커밋 전)
./gradlew spotlessApply      # Google Java Style로 자동 정리
./gradlew bootJar            # 실행용 jar (build/libs/)
```

- 비밀 값(AI 키·관리자 계정·마스터 키)은 `backend/config/application-local.yml`(git 제외). 견본은 `application-local.example.yml`. `.env`는 쓰지 않는다.
- 마스터 키 새로 만들기: `openssl rand -base64 32`

### 실시간 로그 (AI 분석·로그인·옷 등록을 한눈에)

```bash
python3 backend/scripts/live-log.py      # DB 기록을 1초마다 따라 본다 (Ctrl+C로 종료)
docker compose logs -f backend           # 서버 로그는 이쪽에서
```

## 4. 앱 (`mobile/`, Expo)

```bash
cd mobile
npm install                 # 처음 한 번
npx expo start              # 실제 서버 연결 (기본)
npm run start:mock          # 목업 실행: 게스트 모드·기기 목업 분석, 서버 없이
npm run typecheck           # 타입 검사
npx expo-doctor             # Expo 설정·버전 점검
npx expo install <패키지>    # 패키지 추가는 항상 이걸로 (SDK 호환 버전)
```

- `CI=1`로 띄우지 않는다 (파일 감시가 꺼져 코드 수정이 반영되지 않는다).
- 휴대폰에서 연결이 안 되면 같은 Wi-Fi인지, Mac IP가 바뀌지 않았는지 본다. 터널이 필요하면 `npx expo start --tunnel` (이때 API 주소는 `EXPO_PUBLIC_API_URL`로 직접 준다).

### iOS 시뮬레이터

```bash
# Xcode를 쓰도록 한 번 설정 (또는 명령 앞에 DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer)
sudo xcode-select -s /Applications/Xcode.app

cd mobile && npx expo start --ios                 # 시뮬레이터 켜고 Expo Go로 열기
xcrun simctl list devices | grep Booted           # 켜진 시뮬레이터
xcrun simctl io booted screenshot ~/Desktop/s.png # 화면 캡처
xcrun simctl addmedia booted ~/Desktop/옷사진.jpg   # 사진을 시뮬레이터 앨범(사진 앱)에 넣기 (여러 개 가능, jpg·png·heic·mp4)
open -a "/Applications/Xcode.app/Contents/Applications/DeviceHub.app"   # Xcode 27의 시뮬레이터 창
```

- 사진 넣기는 시뮬레이터 창에 사진 파일을 끌어다 놓아도 된다. 넣은 사진은 앱의 "앨범에서 선택"에 바로 보인다.
- 지금 켜진 시뮬레이터가 여러 대면 `booted` 대신 기기 ID를 쓴다 (`xcrun simctl list devices`로 확인).

## 6. 연동 하네스 (`harness/`)

앱의 API 코드로 실제 백엔드를 시험한다. 하네스 전용 DB(`wearly_harness`), Valkey DB 1(`wearly-valkey`, 없으면 `docker compose up -d valkey`로 띄움), 사진 버킷 `wearly-images-harness`(`wearly-minio`, 없으면 `docker compose up -d minio minio-init`), 18080 포트를 쓰므로 compose와 같이 돌려도 된다.

```bash
cd harness
npm install
./run.sh                                 # 전체 시나리오 (백엔드를 18080으로 직접 띄움)
HARNESS_BOOT_TIMEOUT=600 ./run.sh        # 첫 실행에 Gradle 내려받기가 길 때
./run.sh --list                          # 시나리오 목록
./run.sh --only 관리자                    # 일부만
./run.sh --keep                          # 끝나도 백엔드를 남김
./run.sh --external http://localhost:18080   # 이미 떠 있는 서버로 (만료·관리자 시나리오는 건너뜀)
./run.sh --db-only                       # 하네스 DB만 다시 만들기 (Valkey DB 1·하네스 사진 버킷도 비움)
```

## 9. 포트 정리

| 포트 | 쓰는 것 | 겹치면 |
|---|---|---|
| 5433 | DB (compose) | — |
| 6380 | Valkey (compose, 로그인 세션). 개발 서버는 DB 0, 하네스는 DB 1 | 다른 Redis는 보통 6379라 겹치지 않는다 |
| 9000 | MinIO S3 API (compose, 옷 사진). 앱이 서명 URL로 직접 올리고 받으므로 시뮬레이터·휴대폰에서 Mac의 9000에 닿아야 한다 | 다른 MinIO가 쓰면 끄거나 compose 포트를 바꾼다 |
| 9001 | MinIO 웹 콘솔 (compose) | — |
| 8080 | 백엔드 (compose 또는 bootRun) | `docker compose stop backend` 후 bootRun |
| 5173 | 관리자 사이트 (compose 또는 npm run dev) | `docker compose stop admin` 후 npm run dev |
| 8081 | Metro (앱 개발 서버) | 이미 떠 있는 Expo를 끄거나 다른 포트 선택 |
| 18080 | 하네스용 백엔드 | 하네스가 끝나면 스스로 정리 |

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN     # 이 포트를 누가 쓰는지
```
