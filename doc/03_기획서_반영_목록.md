## p.05 브랜드 접점표 — 변경 없음

발견 단계의 접점이 '앱스토어 · SNS 광고'다. 원안(PWA)은 앱스토어에 올라가지 않아 이 표와 맞지 않았다([01](01_기획서_분석.md) 약점 3). 네이티브 앱으로 출시하기로 하면서(D1) 그대로 맞게 됐다. 재방문 단계의 '아침 푸시'도 아래 p.10에서 P0로 올라가 일관된다. 고칠 필요는 없다.

## p.14 옷 등록 — 주요 필드

| 구분 | 현재 | 변경 | 근거 |
|---|---|---|---|
| 제안 | 종류 · 주요 색상 · 패턴 / 계절 · 스타일 · 보유 상태 / 사진 및 대표 이미지 | 핏(슬림·레귤러·오버), 기장, 두께 추가. AI가 값을 제안하고 사용자가 수정한다 | 01 약점 2, 보완 4 |

- 진단의 '실루엣 · 핏'과 추천의 '날씨 적합(소재·두께)'에 쓸 데이터가 지금 필드에는 없다.
- 입력 방식은 이 페이지의 설계 원칙 "AI 분석값은 제안값으로 제공"을 그대로 따른다.
- 목업 앱은 이 필드 대신 세부 종류(셔츠, 와이드 팬츠 등)에서 볼륨과 보온 정도를 추정해 썼다([04_목업_앱.md](04_목업_앱.md) 6~7장).

## p.29 백엔드 설계 — REST API

기존 8개 API는 그대로 두고 인증 API를 추가한다. **확정** (D5)

| METHOD | ENDPOINT | 설명 |
|---|---|---|
| POST | `/api/v1/auth/social/{provider}` | 소셜 로그인 / 자동 가입 |
| POST | `/api/v1/auth/refresh` | 토큰 갱신 |
| POST | `/api/v1/auth/logout` | Refresh Token 폐기 |
| GET / POST / DELETE | `/api/v1/users/me/social-accounts` | 계정 연결·해제 |
| DELETE | `/api/v1/users/me` | 회원 탈퇴 (연결 끊기 + 데이터 삭제) |

## 반영 후 남는 결정 사항

이 목록을 반영해도 기획서에서 아직 정해지지 않은 것들이다.

| 항목 | 현재 상태 | 정할 것 |
|---|---|---|
| 프리미엄 가격 | p.33 등급표에 기능 범위만 있고 가격은 없다 | 월 구독 가격과 무료 체험 여부. 경쟁사 다수가 무료이고, Indyx는 $12.99/월이다([01](01_기획서_분석.md) 2장) |
| 커머스 원칙 문구 | p.25 처방 3순위에 "옷장 안에서 해결이 어려울 때만 — 보유 옷과 코디 수 함께 제시"가 있다. 그러나 구매 연계(p.10 P2, p.33) 전체에 대한 원칙은 없다 | 이 문구를 커머스 전체 원칙으로 올려 메시지("새 옷을 사기 전에, 내 옷장부터")와의 충돌을 정리할지 ([01](01_기획서_분석.md) 보완 6) |
| 성별·체형별 비즈니스 캐주얼 기준 | 정의가 없다 ([01](01_기획서_분석.md) 약점 7) | 추천의 격식 기준을 성별·체형별로 나눌지. 목업 앱은 성별 구분 없이 하나의 기준을 쓴다 |
