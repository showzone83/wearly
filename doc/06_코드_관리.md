# 06. 코드 관리 (옷 속성 값을 DB에서 불러오기)

> 백엔드(`backend/`)와 앱(`mobile/`)이 함께 따르는 계약이다. 초기값은 [06_코드_초기값.json](06_코드_초기값.json) 하나가 원본이다.

## 1. 배경과 범위

옷 등록 화면의 종류·세부 종류·색상·패턴·계절·스타일·보유 상태가 앱 상수, 백엔드 enum, DB CHECK 제약 세 곳에 따로 박혀 있었다. 값을 하나 늘리려면 세 곳을 고치고 앱을 다시 배포해야 했다.

이번 단계에서 바꾸는 것:

- 위 7개 그룹을 DB 코드 테이블로 옮긴다. 서버는 코드 테이블로 검증하고, 앱은 서버에서 받은 코드로 화면·추천 엔진·일러스트를 그린다.
- 값을 늘린다: 종류 6→7(원피스 추가), 세부 종류 15→52, 색 12→22, 패턴 4→7, 스타일 5→7.
- 추천 엔진이 쓰는 속성(보온·볼륨·일러스트 모양·색 밝기·어울리는 색)도 코드의 `attrs`로 옮긴다.

그대로 두는 것: 상황(Occasion)·분위기(Mood)·드레스 코드·근무 형태·감정·주변 반응 같은 추천·기록 로직 값, 격식(1~3 숫자). 코드를 고치는 관리자 화면과 API는 [07_관리자_사이트.md](07_관리자_사이트.md)를 따른다.

## 2. 테이블 (Flyway `V2__codes.sql`)

```sql
CREATE TABLE tb_code_group (
  group_code  VARCHAR(30) PRIMARY KEY,      -- CATEGORY, SUB_TYPE, COLOR, PATTERN, SEASON, STYLE, ITEM_STATUS
  name        VARCHAR(50) NOT NULL,
  description VARCHAR(300),
  sort_order  INT NOT NULL DEFAULT 0,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE tb_code (
  code_id     BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  group_code  VARCHAR(30) NOT NULL REFERENCES tb_code_group(group_code),
  code        VARCHAR(30) NOT NULL,
  label       VARCHAR(50) NOT NULL,          -- 한국어 표시 이름
  parent_code VARCHAR(30),                   -- SUB_TYPE만: CATEGORY 코드
  sort_order  INT NOT NULL DEFAULT 0,
  active      BOOLEAN NOT NULL DEFAULT TRUE, -- false면 새로 고를 수 없지만, 이미 저장된 값의 이름은 보여 준다
  attrs       JSONB NOT NULL DEFAULT '{}',
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (group_code, code)
);
```

- 초기값은 JSON의 내용 그대로 INSERT한다 (코드·라벨·parent·sortOrder·attrs).
- 기존 CHECK 제약을 지운다: `tb_wardrobe_item`의 category·sub_type·color·pattern·status·seasons·styles, `tb_user_profile`의 colors·moods. 검증은 서버가 코드 테이블로 한다.
- 코디 칸에 `DRESS`를 추가한다: `tb_outfit_item`·`tb_daily_look_item`의 item_role CHECK에 'DRESS'를 넣는다.
- 기존 값은 모두 새 코드에 그대로 있으므로 데이터 변환은 없다.

## 3. 그룹별 attrs

| 그룹 | attrs | 쓰는 곳 |
|---|---|---|
| CATEGORY | `slot`: `TOP`·`BOTTOM`·`DRESS`·`OUTER`·`SHOES`·`BAG` 또는 `null`(코디에 안 들어감) | 추천 코디 칸 |
| SUB_TYPE | `volume`(-1·0·1), `warmth`(0~3), `shape`(일러스트 모양 키) | 실루엣 진단, 날씨 적합, 일러스트 |
| COLOR | `hex`, `neutral`(bool), `light`(0~1), `pairs`(어울리는 색 코드 배열, 양방향) | 색상 조화 점수, 일러스트, 색 칩 |
| ITEM_STATUS | `recommendable`(bool) | 추천 후보에서 빼기 (세탁·수선 중) |
| PATTERN·SEASON·STYLE | 없음 | — |

SUB_TYPE의 `parent_code`는 CATEGORY 코드다. 서버와 앱 모두 아이템의 `subType`이 `category`의 하위인지 확인한다.

## 4. API

### `GET /api/v1/codes` (인증 불필요)

```json
{
  "version": "2026-10-17T05:00:00.000Z#139",
  "groups": [
    {
      "group": "CATEGORY",
      "name": "종류",
      "codes": [
        { "code": "TOP", "label": "상의", "parent": null, "sortOrder": 10, "active": true, "attrs": { "slot": "TOP" } }
      ]
    }
  ]
}
```

- 그룹은 `tb_code_group.sort_order`, 코드는 `sort_order` 순서. 비활성 코드도 `active: false`로 내려 준다(저장된 아이템의 이름을 보여 주려고).
- `version`은 코드 테이블이 바뀌면 달라지는 문자열(예: `max(updated_at)` + 개수). 응답에 `ETag: "<version>"`을 붙이고, `If-None-Match`가 같으면 304를 준다.
- 공개 경로로 둔다(`/api/v1/codes`). 로그인 전 화면에서도 쓸 수 있게.

### 검증 규칙 (기존 API 동작 변경)

- 아이템 등록·수정·일괄 등록: category·subType·color·pattern·status·seasons[]·styles[]가 각 그룹에 있는 코드인지, subType의 parent가 category인지 확인한다. 실패하면 400 `VALIDATION_FAILED`와 `fieldErrors`.
- **새로 고르는 값은 활성 코드만** 허용한다. PATCH에서 바꾸지 않은 필드는 비활성이어도 그대로 둔다.
- 프로필 `colors`·`moods`도 COLOR·STYLE 코드로 검증한다.
- 목록 필터(`category`·`status`·`color`)의 모르는 값은 지금처럼 400.
- `/wardrobe/stats`의 `byCategory`·`byStatus`는 활성 코드 전부를 키로 넣는다(0 포함). 비활성 코드에 아이템이 있으면 그 키도 넣는다.

### AI 분석

- Claude 요청의 JSON 스키마 enum과 프롬프트의 허용 값 목록을 **활성 코드에서 만든다**(코드와 한국어 라벨을 함께 준다). 세부 종류는 종류별로 묶어 보여 준다.
- 응답 검증도 코드 테이블 기준(활성 코드, parent 일치).
- 목업 공급자도 활성 코드에서 고른다.

### 캐시

서버는 코드를 메모리에 캐시한다(시작할 때 읽고, 관리자 API로 코드가 바뀌면 다시 읽는다).

## 5. 앱

- 시작할 때 `GET /codes`로 코드를 받아 저장소에 캐시한다(재실행 시 캐시를 먼저 쓰고 뒤에서 갱신, `version`이 같으면 그대로).
- **기본 실행**에서 코드를 한 번도 받지 못했으면(첫 실행 + 서버 불가) 재시도 화면을 보여 준다. 목업 값으로 대신하지 않는다.
- **목업 실행**(`npm run start:mock`)에서만 앱에 넣어 둔 초기값(JSON 사본)을 쓴다.
- 종류·세부 종류·색·패턴·계절·스타일·보유 상태는 문자열 타입으로 바꾸고, 라벨·속성은 코드에서 읽는다. 코디 칸(Slot)은 앱 로직이라 `TOP|BOTTOM|DRESS|OUTER|SHOES|BAG`로 고정한다.
- 추천 엔진: 코디는 `상의+하의` 또는 `원피스` 중 하나로 만든다(원피스면 상의·하의 칸을 비운다). 색 조화는 `attrs.pairs`, 보온·볼륨은 SUB_TYPE `attrs`, 추천 후보는 ITEM_STATUS `recommendable`.
- 일러스트: `attrs.shape` 키로 모양을 고른다. 앱이 모르는 모양 키면 같은 종류의 기본 모양으로 그린다(관리자가 새 세부 종류를 추가해도 깨지지 않게).
- 모르는 코드(앱 캐시보다 새 값)는 코드 문자열을 그대로 라벨로 보여 주고 죽지 않는다.
