# 25. 친구 초대·추천인

> 2026-10-25, 이슈 [#16](https://github.com/showzone83/wearly/issues/16). 회원이 앱을 다른 사람에게 카카오톡·문자 등으로 알리고, 새 회원은 가입할 때 초대 코드를 넣어 추천인을 남긴다. **초대한 이력**과 **초대 코드로 가입한 이력**을 서버에 쌓고 관리자 사이트에서 본다.

## 1. 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 공유 방법 | OS 공유 시트(`Share.share`, 카카오톡·메시지 등 설치된 앱이 뜸) + 문자(`expo-sms`) + 코드 복사(`expo-clipboard`) | 카카오 API 키·개발 빌드 없이 Expo Go에서 바로 된다. 카카오톡 템플릿 카드(이미지·버튼)는 카카오 SDK·앱 키가 필요해 카카오 로그인(02 문서 D5)과 함께 한다 |
| 초대 코드 | 회원당 하나, 8자, 0·1·I·L·O를 뺀 대문자·숫자 31자. 화면에는 `XXXX-XXXX` | 말로 불러도 헷갈리지 않게. 약 8.5×10^11가지 |
| 코드 만드는 때 | 회원이 처음 초대 화면을 열 때 (`GET /users/me/invite`) | 기존 회원 백필이 필요 없다. 겹치면 최대 5번 다시 만든다 |
| 없는 코드로 가입 | **가입은 막지 않는다.** 추천인 없이 가입하고 이력에 `UNKNOWN_CODE`로 남긴다 | 가입을 놓치지 않는 쪽을 골랐다(사용자 결정). 관리자가 틀린 코드를 볼 수 있다 |
| 추천인 관계의 기준 | `tb_invite_signup.result = 'LINKED'`인 행 하나 | `tb_user`는 바꾸지 않는다. 이력 표 하나로 관계·이력을 함께 본다 |
| 초대 링크 | 아직 없음 (`mobile/src/lib/invite.ts` `INVITE_URL = null`) | 스토어 등록·공개 웹 체험판이 없어 https 링크 대상이 없다. 생기면 공유 문구에 한 줄 더한다. 앱은 `wearly://auth?invite=코드`로 열면 가입 화면에 코드가 채워진다 |
| 보상 | 없음 | 이슈 범위 밖. 이력이 있으니 나중에 더할 수 있다 |

## 2. 테이블 (`V26__invite.sql`, invite 컨텍스트)

| 테이블 | 컬럼 | 내용 |
|---|---|---|
| `tb_user_invite_code` | `user_id` PK(FK `tb_user` CASCADE), `code` UNIQUE, `created_at` | 회원별 초대 코드 |
| `tb_invite_share` | `invite_share_id`, `user_id`(CASCADE), `channel`(`SHARE`·`SMS`·`COPY`), `created_at` | **초대한 이력**. 앱에서 보낼 때마다 한 행 (같은 방법 60초에 한 번, 하루 30건까지, 6.1) |
| `tb_invite_signup` | `invite_signup_id`, `user_id` UNIQUE(CASCADE), `referrer_id`(**SET NULL**), `entered_code`(정리한 값, 20자까지), `result`(`LINKED`·`UNKNOWN_CODE`), `created_at` | **초대 코드 가입 이력**. 코드를 넣고 가입한 경우만, 가입자당 한 행. 추천인이 탈퇴해도 이력은 남는다 |

- 코드 넣기는 `INSERT … ON CONFLICT DO NOTHING`으로 한다. PostgreSQL은 고유 제약 위반이 나면 트랜잭션 전체가 실패하므로, 예외를 잡아 다시 시도하는 대신 넣었는지를 다시 읽어 확인한다.
- 모든 테이블·컬럼에 `COMMENT ON`이 있다 (08 문서 8장).

## 3. API

| 메서드 | 경로 | 내용 |
|---|---|---|
| POST | `/auth/signup` | 본문에 `inviteCode`(선택, 20자까지). 대소문자·공백·하이픈은 무시한다. 회원·자격 증명을 저장한 뒤 **같은 트랜잭션**에서 가입 이력을 남긴다 |
| GET | `/users/me/invite` | `{ inviteCode, invitedCount }`. 없으면 만든다 |
| POST | `/users/me/invite/shares` | `{ channel: SHARE \| SMS \| COPY }` → 204. 틀리면 400 `VALIDATION_FAILED`(`channel` `NOT_ALLOWED`) |
| GET | `/users/me/invite/friends` | `[{ name, joinedAt }]` 내 코드로 가입한 친구, 최근 가입순, 최대 100명 |
| GET | `/admin/invites/signups?q=&result=` | 가입 이력 (가입자·입력 코드·결과·추천인). 07 문서 4장 |
| GET | `/admin/invites/shares?q=&channel=` | 초대한 이력 (회원·방법). 07 문서 4장 |
| GET | `/admin/users` | 항목에 `referrerId`·`referrerEmail`·`referrerName`·`invitedCount` |

새 오류 코드는 없다. 앱 API 계약은 05 문서 6장 "친구 초대".

## 4. 백엔드 구조

- 새 컨텍스트 `invite` (`HexagonalArchitectureTest.CONTEXTS`에 추가).
  - domain: `InviteCodes`(만들기·정리·형식, `auth`의 `RecoveryCodes`를 본뜸), `InviteChannel`, `InviteSignupResult`
  - port.in: `InviteUseCase`(`myInvite`·`recordShare`·`invitedFriends`·`recordSignup`)
  - port.out: `InviteCodePort`·`InviteHistoryPort`(JPA), `InviteQueryPort`(MyBatis `mapper/invite/InviteMapper.xml`), `InviteSharePolicyPort`(Valkey `ValkeyInviteSharePolicyAdapter`, 6.1)
  - web: `InviteController` `/api/v1/users/me/invite`
- `auth`의 `AuthService.signup`이 `InviteUseCase.recordSignup`을 입력 포트로 부른다 (컨텍스트 사이는 입력 포트로만).
- 관리자 이력은 `admin` 컨텍스트의 `AdminInviteUseCase`·`AdminInviteQueryPort`(MyBatis `mapper/admin/AdminInviteMapper.xml`), 회원 목록 추천인은 `AdminQueryMapper.findUsers`의 `LEFT JOIN`.
- 테스트: `InviteCodesTest`, `InviteServiceTest`(가짜 포트, 충돌 재시도·UNKNOWN_CODE), `InviteIntegrationTest`(실제 HTTP), `AuthServiceTest`(가입이 코드를 넘김), `ApiResponseSnapshotTest`(초대 코드는 `<inviteCode>` 자리표시자), 하네스 `scenarios/invite.ts` 2개.

## 5. 앱

- **가입 화면** (`app/auth.tsx`): 가입 탭에서 비밀번호 아래 "초대 코드 (선택)". 입력하면 대문자·`XXXX-XXXX`로 보인다. URL `invite` 값이 있으면 가입 탭으로 열고 미리 채운다.
- **친구 초대 화면** (`app/invite.tsx`, 더보기 > 친구 초대, 계정 사용자만):
  - 내 코드와 "코드 복사"(복사하면 버튼이 "복사했어요"로 바뀐다)
  - "카카오톡·다른 앱으로 공유": OS 공유 시트. 웹 체험판에서는 숨긴다
  - "문자로 보내기": `SMS.isAvailableAsync()`가 true일 때만(웹·iOS 시뮬레이터는 숨김)
  - "초대로 가입한 친구 N명"과 이름·가입일 목록
- 문구는 `lib/invite.ts` `inviteMessage`. Android 공유 시트는 `url`을 따로 받지 않아 링크도 문구 안에 넣는다.
- 보낼 때마다 `POST /users/me/invite/shares`로 이력을 남긴다. 실패해도 화면은 막지 않는다(경고 로그만). 공유·문자는 열려 있는 동안 다시 누를 수 없고, 복사 기록은 화면에서 처음 한 번만 보낸다 (6.1).

## 6. 이력의 의미와 한계

| 이력 | 남는 때 | 한계 |
|---|---|---|
| 초대한 이력 `SHARE` | 공유 시트를 열고 iOS에서 닫지 않았을 때 | **Android는 실제로 보냈는지 알 수 없다** (`Share.share`가 늘 성공으로 끝남). 연 기록으로 본다 |
| 초대한 이력 `SMS` | 문자 앱을 열고 취소하지 않았을 때 | Android는 결과가 늘 `unknown`이라 보낸 것으로 센다 |
| 초대한 이력 `COPY` | 코드 복사 | 복사한 뒤 실제로 보냈는지는 모른다 |
| 가입 이력 `LINKED` | 맞는 코드로 가입 | 소셜 로그인이 들어오면 그 가입 흐름에도 초대 코드 칸을 더해야 한다 |
| 가입 이력 `UNKNOWN_CODE` | 틀린 코드로 가입 | 형식이 아닌 입력(예: 한글)도 정리해서 그대로 남긴다 |

코드 없이 가입하면 가입 이력이 없다. 관리자가 가입한 회원(`ensureAdmin`·SSO)은 초대 코드를 받지 않는다.

### 6.1 연속 클릭·반복 호출 막기 (2026-10-25)

`POST /users/me/invite/shares`를 연타하거나 스크립트로 부르면 이력이 끝없이 쌓여 DB를 채우고 관리자 이력도 의미를 잃는다. 그래서 서버와 앱 양쪽에서 막는다.

| 어디 | 규칙 | 걸리면 |
|---|---|---|
| 서버 쿨다운 | 같은 회원·같은 방법은 **60초에 한 번** (Valkey `wearly:invite:share:cool:<회원>:<방법>`, 60초) | 기록하지 않고 **204** |
| 서버 하루 상한 | 회원당 하루(한국 날짜) **30건** (Valkey `wearly:invite:share:day:<날짜>:<회원>`, 2일) | 기록하지 않고 **204**. 처음 걸릴 때 `warn` 로그 한 번 |
| 앱 공유·문자 | 시트·문자 앱이 열려 있는 동안 버튼을 막는다 (ref로 같은 순간의 두 번째 탭까지) | 두 번 뜨지 않는다 |
| 앱 코드 복사 | 클립보드에는 매번 넣지만 서버 기록은 이 화면에서 처음 한 번만 | 호출 자체를 줄인다 |

- 쿨다운과 하루 상한은 Lua 스크립트 하나(`ValkeyInviteSharePolicyAdapter`)로 확인해 동시에 와도 넘지 않는다. 쿨다운에 걸린 요청은 하루 수를 세지 않는다. 하루 상한을 넘은 시도는 센다(스크립트 의심 확인용).
- 오류 대신 204로 끝내는 이유: 이력은 통계용이라 빠져도 기능에 문제가 없고, 새 오류 코드·앱 문구가 필요 없다. 한도 값은 `InviteSharePolicy`(`COOLDOWN`·`DAILY_LIMIT`) 상수다.
- 가입 때 코드 맞히기는 응답에 맞았는지가 나오지 않아(늘 201) 코드를 알아낼 단서가 없다. 가입 API 자체의 횟수 제한은 아직 없다(별도 과제).

## 7. 확인

```bash
cd backend && ./gradlew check                     # InviteIntegrationTest 포함
cd harness && ./run.sh --only 친구                  # 하네스 친구 초대 2개
docker exec wearly-postgres psql -U wearly -d wearly -c "select s.created_at, u.email, s.entered_code, s.result, r.email as referrer from tb_invite_signup s join tb_user u on u.user_id = s.user_id left join tb_user r on r.user_id = s.referrer_id order by s.created_at desc limit 20"
```

공유 시트에 카카오톡이 뜨는지, 문자 앱이 열리는지는 실제 휴대폰(SDK 58 Expo Go)에서 확인한다.
