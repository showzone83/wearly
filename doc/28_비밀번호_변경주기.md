# 28. 비밀번호 변경 주기 개발 계획

> 작성일: 2026-10-25 · 이슈 [#21](https://github.com/showzone83/wearly/issues/21) · 상태: **0~3단계 구현함**(결정 확정·백엔드 상태·변경·연장 API·서버 푸시·앱 변경 화면과 알림 창), 4~5단계 계획

비밀번호를 바꾼 지 정해 둔 기간(기본 90일)이 지나면 바꾸라고 알리고, 회원이 "연장"을 고르면 그 기간만큼 미룬다. 앱 회원도 비밀번호를 바꿀 수 있게 한다.

이 문서는 이슈 #21 본문을 코드와 대조해 단계별 작업으로 나눈 것이다. 2장 결정은 2026-10-25에 확정했다. 구현한 단계는 그 장을 실제 내용으로 고친다.

## 1. 1단계 전 코드

- 비밀번호 변경은 관리자 사이트에만 있다: `POST /admin/me/password` → [`AdminMeService.changePassword`](../backend/src/main/java/app/wearly/admin/application/service/AdminMeService.java) → `AuthService.changePassword`. 현재 비밀번호 확인(403 `REAUTH_FAILED`), 규칙(`PasswordPolicy`, 8~64자·영문과 숫자) 확인, 해시 저장, 지금 세션만 남기고 다른 세션을 끊는다. 변경 이력 `ADMIN_PASSWORD_CHANGE`.
- 앱에는 비밀번호 변경이 없다(더보기 탭에 로그아웃·회원 탈퇴만).
- 자격 증명 `tb_user_local_credential`(V1)에는 `password_hash`·`last_login_at`·`created_at`·`updated_at`뿐이라 비밀번호를 언제 정했는지 모른다.
- 서버 푸시는 `PushNotifyUseCase.notifyUser(userId, PushNoticeDto)`로 다른 컨텍스트가 보낼 수 있다(옷장 도우미가 쓰는 중). 앱은 푸시를 누르면 `data.type`으로 화면을 고른다([`planNotify.ts`](../mobile/src/lib/planNotify.ts) `openFromResponse`).
- 로그인 이력 `tb_auth_event`(`ck_auth_event_type`, 마지막 변경 V22).

## 4. 단계별 계획

### 1단계 — 백엔드: 상태·변경·연장 — 구현함 (2026-10-25)

**구현한 것**

- **V31** [`V31__password_change_interval.sql`](../backend/src/main/resources/db/migration/V31__password_change_interval.sql): 자격 증명에 `password_changed_at`(이미 있는 행은 마이그레이션 시각)·`password_postponed_at`·`password_reminded_at`(2단계에서 씀), `ck_auth_event_type`에 `PASSWORD_CHANGED`·`PASSWORD_POSTPONED`. 모든 컬럼에 코멘트.
- **규칙** [`PasswordChangePolicy`](../backend/src/main/java/app/wearly/auth/domain/PasswordChangePolicy.java)(순수): 기한 = max(정한 시각, 연장 시각) + 주기, 기한 시각부터 "지남", 주기 0이면 기한 없음. 설정은 [`PasswordProperties`](../backend/src/main/java/app/wearly/auth/config/PasswordProperties.java)(`wearly.auth.password.*`)를 `PasswordConfig`가 규칙으로 바꾼다. 음수 주기·0개 묶음이면 서버가 시작하지 않는다.
- **유스케이스** [`PasswordUseCase`](../backend/src/main/java/app/wearly/auth/application/port/in/PasswordUseCase.java) / `PasswordService`: `status`·`change`·`postpone`. 비밀번호 변경은 원래 `AccountUseCase.changePassword`(관리자 전용)에 있던 것을 옮겨 앱·관리자가 같이 쓴다(현재 비밀번호 확인은 `AccountUseCase.passwordMatches`의 더미 비교 그대로). 로그인 이력의 기기 정보는 지금 세션의 것.
- **API**: 앱 [`PasswordController`](../backend/src/main/java/app/wearly/auth/adapter/in/web/PasswordController.java)(`/users/me/password`, doc/05), 관리자 `AdminMeController`에 `GET /admin/me/password`·`POST /admin/me/password/postpone`(doc/22·07).
- **테스트**: `PasswordChangePolicyTest`(기한·연장·끔·잘못된 설정), `AuthServiceTest`(변경하면 주기 다시 시작·연장 기록 지움·`PASSWORD_CHANGED`·같은 비밀번호 `NOT_ALLOWED`·연장·비밀번호 없음/기능 끔 404), `PasswordIntegrationTest`(실제 HTTP 4개: 가입하면 90일 기한·401, 변경 400·403·204 → 다른 기기 401·옛 비밀번호 로그인 실패·로그인 이력, 기한을 당긴 뒤 연장, 관리자 상태·연장·변경 이력·일반 회원 403). API 스냅샷에 `users.password`·`users.password.same`·`users.password.postpone`·`admin.me.password`.

**원래 계획(참고)**

- **V31** `tb_user_local_credential`에 `password_changed_at`(NOT NULL, 기본 now())·`password_postponed_at`·`password_reminded_at`(코멘트 포함). `ck_auth_event_type`에 `PASSWORD_CHANGED`·`PASSWORD_POSTPONED`.
- **설정** `wearly.auth.password.*`: `change-interval`(P90D), `reminder-cron`(`0 0 10 * * *`), `reminder-batch`(500), `reminder-enabled`(true).
- **앱 API** (로그인 필요):
  | API | 응답 |
  |---|---|
  | `GET /users/me/password` | `{ changedAt, dueAt, due, intervalDays }`. 기능이 꺼졌거나 비밀번호가 없으면 `dueAt = null`, `due = false` |
  | `POST /users/me/password` `{ currentPassword, newPassword }` | 204. 현재 비밀번호가 틀리면 403 `REAUTH_FAILED`, 규칙에 안 맞으면 400 `VALIDATION_FAILED`(`newPassword` `INVALID_FORMAT`), 같은 비밀번호면 `NOT_ALLOWED` |
  | `POST /users/me/password/postpone` | 200 `{ dueAt }`. 기능이 꺼졌거나 비밀번호가 없으면 404 |
- **관리자 API**: `GET /admin/me/password`, `POST /admin/me/password/postpone`(변경 이력 `ADMIN_PASSWORD_POSTPONE`). 비밀번호 변경 `POST /admin/me/password`는 그대로이고 같은 경로를 탄다.

### 2단계 — 백엔드: 서버 푸시 — 구현함 (2026-10-25)

**구현한 것**

- **예약 작업** [`PasswordReminderScheduler`](../backend/src/main/java/app/wearly/auth/adapter/in/schedule/PasswordReminderScheduler.java): `wearly.auth.password.reminder-cron`(한국 시간, 기본 매일 10:00), `reminder-enabled=false`면 만들지 않는다(테스트).
- **작업** [`PasswordReminderService`](../backend/src/main/java/app/wearly/auth/application/service/PasswordReminderService.java)(`PasswordReminderUseCase.remindDue`): 기능이 꺼졌으면 아무것도 안 한다. `dueBy = now - 주기`로 대상을 찾고(`reminder-batch`명까지, 기준 시각이 이른 순), 회원마다 처리권을 잡은 뒤 푸시. 잡은 뒤에는 푸시가 실패하거나 기기가 없어도 이 주기에는 다시 보내지 않는다. 한 명이 실패해도 계속하고 로그에는 건수만(대상·알림·기기 도착·건너뜀·실패).
- **대상 조건**(native SQL, [`LocalCredentialJpaRepository`](../backend/src/main/java/app/wearly/auth/adapter/out/persistence/jpa/LocalCredentialJpaRepository.java)): `tb_user.status = 'ACTIVE'`이고, 기준 시각 `greatest(password_changed_at, password_postponed_at)`이 `dueBy` 이전이고, `password_reminded_at`이 비었거나 기준 시각보다 이르다. 처리권은 같은 조건의 `UPDATE … SET password_reminded_at = now`(서버가 여러 대여도 한 번). 비밀번호를 바꾸면 알림 기록이 지워지고, 연장하면 기준 시각이 알림 시각보다 늦어져 다음 기한에 다시 보낸다.
- **푸시** [`PasswordReminderNotice`](../backend/src/main/java/app/wearly/auth/domain/PasswordReminderNotice.java): 제목 "비밀번호를 바꿔 주세요", 본문 "비밀번호를 바꾼 지 90일이 지났어요. 눌러서 바꾸거나 90일 연장할 수 있어요.", `data.type = password-change-due`, 안드로이드 채널 `account`. notify의 `PushNotifyUseCase`로 보낸다(출력 포트 `PasswordNoticePort` → `PasswordNoticeNotifyAdapter`, 옷장 도우미와 같은 방식).
- **테스트**: `PasswordReminderServiceTest`(처리권 잃음·실패·기기 없음 집계, 묶음 수, 기능 끔), `PasswordReminderIntegrationTest`(Expo 가짜 서버로 실제 푸시 3개: 기한 지난 회원만·제목·본문·type·채널, 같은 주기 다시 안 보냄, 연장하면 다음 기한에 한 번 더, 정지 회원·비밀번호 바꾼 회원 제외).

**원래 계획(참고)**

- `PasswordReminderScheduler`(매일 10:00 KST) → 기한이 지났고 이번 주기에 아직 안 보낸 ACTIVE 회원을 찾아, `UPDATE … WHERE`로 처리권을 잡은 뒤 푸시. 제목 "비밀번호를 바꿔 주세요", `data.type = password-change-due`. 실패해도 다음 회원은 계속.

### 3단계 — 앱 — 구현함 (2026-10-25)

**구현한 것**

- **규칙** [`lib/passwordRules.ts`](../mobile/src/lib/passwordRules.ts)(순수, `tests/passwordRules.test.mjs` 5개): 비밀번호 형식(`passwordProblem`, 로그인 화면에서 옮김), 변경 화면 입력 확인(지금 비밀번호·형식·같은 비밀번호·확인 칸), 기한 창·연장·변경 완료 문구(서버 `intervalDays`, 없으면 90일), `password-change-due` 알아보기, 채널 `account`.
- **API 모듈**: `api.password.status()`·`change({ currentPassword, newPassword })`·`postpone()` (doc/05 8장).
- **변경 화면** [`app/password.tsx`](../mobile/src/app/password.tsx)(`/password`): 지금·새·확인 비밀번호(가려서 입력, 자동 완성 `current-password`·`new-password`). `REAUTH_FAILED`는 지금 비밀번호 칸에, `NOT_ALLOWED`·`INVALID_FORMAT`은 새 비밀번호 칸에. 바꾸면 뒤로 가며 "비밀번호를 바꿨어요 — 다른 기기에서는 로그아웃됐어요". 기한이 지났으면 위에 안내와 "90일 연장" 버튼, 아니면 "다음에 바꿀 날".
- **더보기 탭**: 계정 칸 맨 위에 "비밀번호 변경"(계정 모드만).
- **알림 창** [`lib/passwordReminder.ts`](../mobile/src/lib/passwordReminder.ts): 화면이 준비되면(`_layout` `usePasswordReminder`)과 로그인한 뒤(`auth.tsx`) 서버에 묻고, 기한이 지났으면 "비밀번호를 바꿀 때가 됐어요" 창(`바꾸기` → `/password`, `90일 연장` → 연장하고 "○월 ○일에 다시 알려 드릴게요"). 같은 실행에서 같은 계정은 한 번만 묻는다. 뒤로 가기·바깥 누르기로 닫으면 다음 실행에 다시 묻는다. 게스트·목업 실행·예전 서버(404)는 조용히 넘어간다.
- **두 갈래 창**: 앱 대화상자에 `cancelLabel`·`onCancel`을 더해(`lib/dialogQueue.ts`·`useDialogStore`·`DialogHost`) 왼쪽 버튼에도 동작을 둘 수 있게 했다. `components/ui`의 `choose(title, message, { ok, onOk, cancel, onCancel })`. 뒤로 가기·바깥 누르기는 어느 쪽도 부르지 않는다.
- **알림 누르기**: `planNotify.ts`의 `openFromResponse`에서 `password-change-due` → `/password?due=1`. 안드로이드 채널 `account`("계정 알림")를 만든다.
- **오류 문구**: `errorText.ts` 필드 `newPassword`(INVALID_FORMAT·NOT_ALLOWED·REQUIRED)·`currentPassword`와 라벨.
- **하네스**: `계정` 그룹 `password` 시나리오(상태 90일 → 같은 비밀번호 400·틀린 비밀번호 403 → 변경 → 다른 기기 onAuthLost·옛 비밀번호 401·새 비밀번호 로그인 → 연장 90일).
- **확인**: 앱 `typecheck`·단위 테스트 52개·`check:errors`(57개 그대로)·expo-doctor 20/20, 하네스 전체 64개 통과. 브라우저(390×844): 하네스 백엔드(18080)를 보는 Expo 웹으로, 기한을 95일 전으로 당긴 계정에 로그인 → 홈 위에 "비밀번호를 바꿀 때가 됐어요" 창(90일 연장 / 바꾸기) → 바꾸기 → `/password`에 안내·"90일 연장" 버튼 → 새 비밀번호로 바꾸기 → 홈에 "비밀번호를 바꿨어요" 안내. DB에 `password_changed_at` 새 시각, 로그인 이력 `PASSWORD_CHANGED`·`FORCED_LOGOUT`. 실제 휴대폰·서버 푸시 누르기는 확인하지 못했다(Dev Build 필요).

**원래 계획(참고)**
