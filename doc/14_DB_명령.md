# 14. DB 명령 모음 (로컬 PostgreSQL)

> 로컬 개발 DB를 들여다보고 고칠 때 쓰는 명령. 2026-10-17 기준 스키마(Flyway V1~V5). 조회문은 모두 실제로 돌려 확인했다.

## 1. 접속

| 항목 | 값 |

## 3. 자주 쓰는 조회

### 회원

```sql
-- 회원 목록과 옷 수
select u.user_id, u.email, u.name, u.role, u.status, count(i.item_id) as items
from tb_user u left join tb_wardrobe_item i on i.user_id = u.user_id
group by u.user_id order by u.user_id;

-- 회원별 살아 있는 Refresh 토큰 수 (로그인한 기기 수)
select u.email, count(*) filter (where t.revoked_at is null and t.expires_at > now()) as active
from tb_refresh_token t join tb_user u using (user_id)
group by u.email order by 2 desc;
```

### 옷장

```sql
-- 한 회원의 옷 목록
select i.item_id, i.name, i.category, i.sub_type, i.color, i.pattern, i.status, i.worn_count, i.last_worn_at
from tb_wardrobe_item i join tb_user u using (user_id)
where u.email = 'test@wearly.app'
order by i.item_id;

-- 최근 하루 사이에 등록된 옷
select i.item_id, i.name, i.category, i.sub_type, i.color,
       i.created_at at time zone 'Asia/Seoul' as created, u.email
from tb_wardrobe_item i join tb_user u using (user_id)
where i.created_at > now() - interval '1 day'
order by i.item_id desc;
```

### AI 사용 기록

```sql
-- 최근 AI 호출 (사진 분석·코디 추천·관리자 시험)
select l.created_at at time zone 'Asia/Seoul' as at, u.email, l.feature, l.provider, l.model,
       l.status, l.latency_ms, l.error_code
from tb_ai_analysis_log l left join tb_user u using (user_id)
order by l.created_at desc limit 20;

-- 최근 7일 공급자·기능별 성공·실패·평균 지연·토큰
select provider, feature,
       count(*) filter (where status = 'SUCCESS') as ok,
       count(*) filter (where status = 'FAILED')  as fail,
       round(avg(latency_ms)) as avg_ms, sum(input_tokens) as in_tok, sum(output_tokens) as out_tok
from tb_ai_analysis_log
where created_at >= now() - interval '7 days'
group by provider, feature order by 1, 2;

-- 오늘(한국 시간) 회원별 사진 분석 성공 횟수 (일일 한도 계산과 같은 기준)
select u.email, count(*) as used_today
from tb_ai_analysis_log l join tb_user u using (user_id)
where l.status = 'SUCCESS' and l.feature = 'ITEM_ANALYZE'
  and (l.created_at at time zone 'Asia/Seoul')::date = (now() at time zone 'Asia/Seoul')::date
group by u.email;
```

AI 코디 추천 한도는 같은 쿼리에서 `feature = 'OUTFIT_RECOMMEND'`로 본다.

### AI 공급자와 키

```sql
-- 공급자 설정과 웹 입력 키 유무 (키 값 자체는 암호문이라 볼 수 없다)
select p.provider_id, p.type, p.model, p.enabled, p.priority, p.api_key_env,
       s.last4 is not null as web_key, s.updated_at at time zone 'Asia/Seoul' as key_updated
from tb_ai_provider p left join tb_ai_provider_secret s using (provider_id)
order by p.priority;
```

## 4. 데이터 고치기

> **관리자 사이트나 API로 할 수 있는 일은 그쪽으로 한다.** SQL로 직접 고치면 변경 이력이 남지 않고, 서버의 코드·키 캐시가 바로 갱신되지 않는다(코드를 SQL로 바꿨다면 백엔드를 재시작). 고치기 전에 `begin;`으로 시작해 결과를 보고 `commit;` 또는 `rollback;` 한다.

```sql
begin;
-- 여기서 update / delete
select ...;   -- 결과 확인
commit;       -- 문제 있으면 rollback;
```

### 2026-10-17에 실제로 한 수정

```sql
-- 깨진 관리자 이름 바로잡기 (.env를 properties(ISO-8859-1)로 읽던 때 만들어진 계정)
update tb_user set name = '관리자', updated_at = now()
where email = 'admin@wearly.app';

-- 원피스 코드가 생기기 전에 등록돼 '하의·스커트'로 들어간 원피스를 원피스로
update tb_wardrobe_item set category = 'DRESS', sub_type = 'DRESS', updated_at = now()
where item_id = 23;

-- 맨투맨이 티셔츠로 들어간 것 바로잡기
update tb_wardrobe_item set sub_type = 'SWEATSHIRT', updated_at = now()
where item_id = 22;
```

옷을 고친 뒤에는 앱을 다시 열어야(또는 다시 로그인) 기기의 옷장이 서버 값으로 맞춰진다.

### 그 밖에 쓸 만한 것

```sql
-- 이름이 한글 인코딩이 깨진 회원 찾기
select user_id, email, name from tb_user where name ~ '[ÃÂâêëìíî]';

-- 회원 정지 풀기 (관리자 사이트 '회원' 화면에서도 된다)
update tb_user set status = 'ACTIVE', updated_at = now() where email = '...';

-- 한 회원의 모든 로그인 끊기 (Refresh 토큰 폐기)
update tb_refresh_token set revoked_at = now()
where user_id = (select user_id from tb_user where email = '...') and revoked_at is null;

-- 테스트용: 오늘 AI 사용 기록을 지워 한도 되돌리기 (로컬에서만, 통계도 같이 사라진다)
delete from tb_ai_analysis_log
where user_id = (select user_id from tb_user where email = 'test@wearly.app')
  and (created_at at time zone 'Asia/Seoul')::date = (now() at time zone 'Asia/Seoul')::date;
```

비밀번호 해시(`tb_user_local_credential.password_hash`), 웹 입력 키 암호문(`tb_ai_provider_secret.ciphertext`)은 직접 고치지 않는다. 키는 관리자 사이트의 AI 공급자 화면에서 넣고 지운다.

## 5. 백업 · 복원 · 초기화

```bash
# 백업 (파일로)
docker exec wearly-postgres pg_dump -U wearly -d wearly -Fc > wearly-$(date +%Y%m%d-%H%M).dump

# 복원 (기존 데이터를 덮어쓴다. 먼저 백엔드를 멈춘다)
docker compose stop backend
docker exec -i wearly-postgres pg_restore -U wearly -d wearly --clean --if-exists < wearly-YYYYMMDD-HHMM.dump
docker compose start backend

# SQL 파일로 내보내기 (읽기 쉬운 형태)
docker exec wearly-postgres pg_dump -U wearly -d wearly --inserts > wearly.sql
```

```bash
# 하네스 DB만 다시 만들기
cd harness && ./run.sh --db-only

# ⚠️ 전체 초기화: DB 볼륨을 지운다. 회원·옷장·키가 모두 사라진다
docker compose down -v
docker compose up -d --build     # Flyway가 V1부터 다시 만든다. 관리자 계정은 config/application-local.yml로 다시 생긴다
```
