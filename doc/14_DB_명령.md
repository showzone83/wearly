### AI 사용 기록

```sql
-- 최근 AI 호출 (사진 분석·코디 추천·관리자 시험)
select l.created_at at time zone 'Asia/Seoul' as at, u.email, l.feature, l.provider, l.model,
       l.status, l.latency_ms, l.error_code
from tb_ai_analysis_log l left join tb_user u using (user_id)
order by l.created_at desc limit 20;

-- 최근 7일 공급자·기능별 성공·실패·평균 지연·토큰
select provider, feature,
       count(*) filter (where status = 'SUCCESS') as ok,
       count(*) filter (where status = 'FAILED')  as fail,
       round(avg(latency_ms)) as avg_ms, sum(input_tokens) as in_tok, sum(output_tokens) as out_tok
from tb_ai_analysis_log
where created_at >= now() - interval '7 days'
group by provider, feature order by 1, 2;

-- 오늘(한국 시간) 회원별 사진 분석 성공 횟수 (일일 한도 계산과 같은 기준)
select u.email, count(*) as used_today
from tb_ai_analysis_log l join tb_user u using (user_id)
where l.status = 'SUCCESS' and l.feature = 'ITEM_ANALYZE'
  and (l.created_at at time zone 'Asia/Seoul')::date = (now() at time zone 'Asia/Seoul')::date
group by u.email;
```

AI 코디 추천 한도는 같은 쿼리에서 `feature = 'OUTFIT_RECOMMEND'`로 본다.

## 4. 데이터 고치기

> **관리자 사이트나 API로 할 수 있는 일은 그쪽으로 한다.** SQL로 직접 고치면 변경 이력이 남지 않고, 서버의 코드·키 캐시가 바로 갱신되지 않는다(코드를 SQL로 바꿨다면 백엔드를 재시작). 고치기 전에 `begin;`으로 시작해 결과를 보고 `commit;` 또는 `rollback;` 한다.

```sql
begin;
-- 여기서 update / delete
select ...;   -- 결과 확인
commit;       -- 문제 있으면 rollback;
```

## 7. Valkey (로그인 세션 · Refresh 토큰)

7차(2026-10-17)부터 Refresh 토큰과 로그인 세션은 Valkey에 있다. 키 구조는 [16_세션_Valkey.md](16_세션_Valkey.md) 3장. 시각 값은 epoch 밀리초.

| 항목 | 값 |
|---|---|
| 컨테이너 | `wearly-valkey` (`docker compose up -d valkey`) |
| 호스트 접속 | `localhost:6380` (컨테이너 안은 6379), 비밀번호 없음 |
| DB 번호 | 개발 서버 `0`, 하네스 `1`(실행할 때마다 비움), 백엔드 테스트는 Testcontainers 따로 |
| 저장 | AOF 켬, 볼륨 `wearly-valkeydata` (재시작해도 로그인이 남는다) |

```bash
# 대화형 접속 (하네스 데이터는 -n 1)
docker exec -it wearly-valkey valkey-cli
docker exec -it wearly-valkey valkey-cli -n 1

# 줄임말 (~/.zshrc)
alias wkv='docker exec -it wearly-valkey valkey-cli'
```

`KEYS` 명령은 쓰지 않는다(키가 많으면 서버를 멈춘다). 목록은 인덱스(`wearly:sessions`)나 `--scan`으로 본다.

```text
# 살아 있는 세션 수 (만료된 멤버는 서버가 목록을 읽을 때 정리하므로 조금 많을 수 있다)
ZCARD wearly:sessions

# 최근 활동한 세션 10개 (score = lastSeenAt, epoch 밀리초)
ZREVRANGE wearly:sessions 0 9 WITHSCORES

# 세션 하나: userId, currentHash, client, userAgent, ip, createdAt, lastRefreshAt, lastSeenAt
HGETALL wearly:session:<sessionId>
TTL wearly:session:<sessionId>            # 남은 초 (Refresh 수명, 회전마다 연장)

# 한 회원의 세션 ID들 (userId는 tb_user.user_id)
SMEMBERS wearly:user:<userId>:sessions

# Refresh 토큰 상태: userId, sessionId, status(ACTIVE·ROTATED·REVOKED), replacedBy, createdAt
HGETALL wearly:rt:<currentHash>

# 세션 키 훑어보기 (KEYS 대신)
SCAN 0 MATCH wearly:session:* COUNT 100

# DB별 키 수
INFO keyspace
```

```bash
# 셸에서 한 줄로: 가장 최근 세션의 내용
docker exec wearly-valkey valkey-cli HGETALL "wearly:session:$(docker exec wearly-valkey valkey-cli ZREVRANGE wearly:sessions 0 0)"

# 하네스 Valkey(DB 1)만 비우기 (개발 DB 0은 그대로)
docker exec wearly-valkey valkey-cli -n 1 FLUSHDB
```

- 로그인을 끊을 때는 키를 직접 지우지 말고 관리자 사이트의 '로그인 사용자' 화면(또는 `DELETE /api/v1/admin/sessions/{sessionId}`·`/admin/users/{id}/sessions`)을 쓴다. 직접 `DEL wearly:session:<id>`만 하면 그 세션은 막히지만 인덱스·회원 집합·Refresh 토큰 상태와 이력(`tb_auth_event`·변경 이력)이 맞지 않는다.
- 모든 로그인을 한꺼번에 끊으려면(로컬에서만) `docker exec wearly-valkey valkey-cli -n 0 FLUSHDB`. 모든 기기가 다시 로그인해야 한다.
