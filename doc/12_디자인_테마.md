# 12. 디자인 테마 (냥깨비 · Closeta)

> 앱(`mobile/`), 관리자 사이트(`admin/`), 백엔드(`backend/`)가 함께 따르는 계약이다. 2026-10-17 결정. 디자인 원본은 `mobile/design/`의 두 보드 PNG.

## 1. 배경과 범위

- 앱 디자인을 두 보드(냥깨비 · Closeta)의 화면 구성으로 바꾼다. **앱 이름은 Wearly를 유지**하고, 보드의 이름(냥깨비·Closeta)은 테마 이름으로만 쓴다.
- 두 테마를 모두 만들고, **관리자 사이트에서 전체 사용자의 테마를 바꾼다**. 앱은 시작할 때 서버 설정을 읽어 그 테마로 그린다.
- 테마마다 마스코트가 다르다: 냥깨비 = 뿔 달린 초록 고양이 도깨비, Closeta = 초록 모자를 쓴 하얀 캐릭터.
- 마스코트는 SVG 벡터로 직접 그린다(보드처럼 렌더링한 일러스트는 아님). 나중에 고품질 그림을 받으면 같은 자세 이름으로 PNG를 바꿔 끼울 수 있게 한다.

## 2. 테마 값 (`mobile/src/data/themes.ts`)

- 순수 TS. 앱과 관리자 사이트가 같이 쓴다.
- `TThemeId = 'nyang' | 'closeta'`, 기본 `nyang`.
- 색 토큰: `bg`, `surface`, `surfaceAlt`, `border`, `primary`, `primaryPressed`, `primarySoft`, `onPrimary`, `text`, `textSub`, `textMuted`, `accent`, `accentSoft`, `chip`, `chipBorder`, `tabBar`, `danger`, `shadow`. 모서리 `radius`(sm 10 · md 16 · lg 22 · xl 28 · pill).
- 보드의 공통 스타일: 크림·아이보리 바탕, 짙은 초록 주 버튼(알약 모양, 높이 52 안팎), 둥근 카드(그림자 아주 약하게), 알약 칩(선택 = 초록 채움 + 흰 글자, 비선택 = 흰 바탕 + 연한 테두리), 굵은 산세리프 제목(세리프 제목을 쓰지 않는다), 하단 탭 5칸(홈 · 내 옷장 · 가운데 초록 원형 + · 코디추천 · 더보기).

## 3. 서버 설정과 전환

### 테이블
`tb_app_setting(setting_key VARCHAR(50) PK, value JSONB NOT NULL, updated_by BIGINT NULL REFERENCES tb_user ON DELETE SET NULL, updated_at TIMESTAMPTZ)`. 초기값 `('theme', '{"themeId":"nyang"}')`.

### API
| 메서드 | 경로 | 권한 | 요청·응답 |
|---|---|---|---|
| GET | `/api/v1/app/config` | 공개 | `{ themeId: "nyang", version: "<updated_at ISO>" }`, `ETag`·`If-None-Match` → 304, `Cache-Control: no-cache` |
| GET | `/api/v1/admin/app/theme` | ADMIN | `{ themeId, updatedAt, updatedBy }` (`updatedBy`는 관리자 이메일 또는 null) |
| PUT | `/api/v1/admin/app/theme` | ADMIN | `{ themeId }` → 위와 같은 모양. 허용 값은 `nyang`·`closeta`, 그 밖은 400 `VALIDATION_FAILED`(`themeId`). 변경 이력 `APP_THEME_UPDATE`(before·after = themeId) |

- CORS에 `If-None-Match` 요청 헤더·`ETag` 노출 포함(코드 API와 같게).
- 테마 목록 자체(색·마스코트)는 앱 코드에 있다. 서버는 어떤 테마를 쓸지만 저장한다.

### 앱 동작
- 시작할 때 코드와 함께 `GET /app/config`를 부른다. 결과를 `useThemeStore`(zustand, 기기 저장)에 넣으면 화면이 바로 그 테마로 다시 그려진다.
- 실패하면(서버 없음·404) 기기에 저장된 테마, 그것도 없으면 `nyang`. 테마는 화면 꾸밈이라 서버 실패가 앱 사용을 막지 않는다.
- 앱이 앞으로 돌아올 때(백그라운드 → 활성)도 한 번 다시 읽는다. 관리자가 바꾸면 사용자가 앱을 다시 열거나 돌아올 때 반영된다.
- 목업 실행(`npm run start:mock`)에서는 서버 대신 마이 탭의 개발용 전환 버튼으로 바꿔 볼 수 있다.

## 4. 마스코트 (`mobile/src/data/mascots/`, 그림 `mobile/assets/mascots/`)

- 그림은 **디자인 보드 PNG(`mobile/design/*.png`)에서 잘라 온 캐릭터를 그대로 쓴다.** 다시 그리거나 고치지 않는다(SVG로 다시 그린 그림은 보드와 달라 버렸다).
- 파일: `assets/mascots/<마스코트>/<자세>.png`. 배경이 있는 **장면 그림**(직사각형)과 배경을 지운 **투명 그림**이 있다.
- 매핑 `MASCOT_IMAGES: Record<마스코트, Record<자세, { file, scene, width, height }>>` (`data/mascots/index.ts`, 순수 TS — RN·Expo·`@/` import 금지, 관리자 사이트가 쓴다). `file`은 `assets/mascots/` 아래 경로, `width`·`height`는 원본 픽셀(장면 그림 높이 계산용).
- 그리는 곳
  - 앱 `components/Mascot.tsx`: `components/mascotSources.ts`(파일 경로 → 정적 `require`)로 `expo-image`에 넘긴다. 투명 그림은 `size` 정사각형에 `contain`, 장면 그림은 가로 `sceneWidth ?? size`, 높이는 비율대로, 모서리 `radius.lg`, `cover`. `useMascotIsScene(pose)`로 화면이 둘레 상자를 그릴지 고른다.
  - 관리자 `admin/src/components/Mascot.tsx`: `import.meta.glob('@app-mascot-images/**/*.png')`로 같은 PNG 주소를 얻어 `<img>`로 그린다.
- 그림을 더하거나 바꿀 때: PNG를 넣고 `data/mascots/index.ts` 매핑과 `components/mascotSources.ts`(require 한 줄)를 함께 고친다. 관리자 사이트는 폴더를 통째로 읽으므로 따로 고칠 것이 없다.

| 자세 | 쓰는 화면 | 냥깨비 | Closeta |
|---|---|---|---|
| `splash` | 스플래시·첫 화면 | 장면: 옷장 위에서 빼꼼 내민 고양이 (`nyang/splash.png`) | 장면: 옷장 앞에서 손 흔드는 모습 (`closeta/splash.png`) |
| `hello` | 홈 인사말 옆, 마이 탭 프로필, 로그인 | 투명: 손 흔드는 얼굴 + 하트 | 투명: 가방 멘 채 손 흔드는 모습 (`closeta/hello.png`) |
| `style` | 온보딩 취향 고르기, AI 추천 진행 | 투명: 엎드려 웃는 얼굴 + 하트 | `hello` 그림 |
| `camera` | 옷 등록 안내 | 투명: 카메라를 든 모습 | `hello` 그림 |
| `closet` | "잊고 있던 옷이 새로운 스타일로" 소개, 빈 옷장·빈 홈·코디 준비 안 됨 | 장면: 옷 더미 위 + 말풍선 | `hello` 그림 |
| `cheer` | 마이 탭 하단, 완료·성공 화면 | 투명: 엎드려 손 흔드는 모습 (가로로 긴 그림) | `hello` 그림 |

- 보드에 Closeta 그림은 두 장면뿐이라 나머지 자세는 `hello`를 쓴다. 보드에 새 그림이 생기면 파일만 더하고 매핑을 바꾼다.
- 장면 그림이 들어가는 자리: 첫 화면은 그대로, 온보딩 STEP 1은 둘레 상자 없이 화면 폭 카드로, 빈 화면(홈 카드 250·내 옷장 290·코디 290)은 `sceneWidth`로 넓게 그린다.

## 5. 화면 (보드 기준)

| 화면 | 바꿀 모습 |
|---|---|
| 스플래시·온보딩 | 마스코트 큰 그림 + 슬로건 + "시작하기 →" 주 버튼 + "로그인" 글자 버튼, 단계 표시 점(●○○), "STEP 1 / 2" 작은 글자, 큰 굵은 제목 + 오른쪽 마스코트 |
| 취향 고르기 | 분위기 칩(알약), 선호 색 동그라미, 자주 입는 옷 아이콘 원형 버튼 |
| 홈 | "안녕하세요!" 인사 + 마스코트, 날씨 카드(해 아이콘·최고 기온·맑음 ›), "내 옷장" 통계 카드 3개(등록한 옷·오늘 추천 코디·활용도), "이런 코디는 어때요? 더보기 ›" 가로 카드 |
| 내 옷장 | 큰 제목, 알약 필터 칩(전체·상의·하의·아우터·원피스…), 3열 둥근 카드 그리드 + 하트, 하단 필터·추가하기(+)·정렬 |
| AI 코디 결과 | 큰 코디 카드(좌우 넘기기), 아이템 썸네일 줄, "이 코디로 입어볼래요 ✨" 주 버튼, 공유·저장·다른 코디 |
| 옷 등록 | "내 옷을 사진으로 등록해주세요!" + 카메라 든 마스코트, 점선 사진 추가 상자, 예시 이미지 줄, "사진 선택하기" |
| 마이 | 프로필(마스코트 아바타 + 이름 + 인사), 메뉴 목록 카드(아이콘 + ›), 하단 마스코트 |

- 화면 기능·흐름은 그대로 둔다(로그인, 코드, AI 분석, AI 코디, 진단, 캘린더 등). 바꾸는 것은 모양이다.
- 옷 사진이 없는 아이템은 일러스트(`GarmentArt`)로 보인다. 보드의 옷 사진 카드에 가깝게: 옅은 칸 바탕(`surfaceAlt`), 옷 아래 옅은 그림자, 몸판 세로 그라데이션(위 밝게·아래 어둡게), 옅은 주름 선(`GARMENT_FOLDS`), 옷 색보다 약간 어두운 얇은 외곽선. 색 규칙은 `garmentTones()`(`data/garmentShapes.ts`)로 관리자 미리보기와 같다.
- 샘플 옷장은 보드 옷장 격자의 옷 사진 18장(`mobile/assets/samples/`)을 쓴다(`data/seed.ts`, `lib/samplePhotos.ts`).

## 6. 관리자 사이트

- 메뉴 "앱 설정 > 테마": 두 테마 카드(이름·설명·색 견본·마스코트 미리보기 6자세), 현재 적용 중 표시, "이 테마로 바꾸기" → 확인 대화상자 → `PUT /admin/app/theme` → 성공 토스트("사용자가 앱을 다시 열면 반영돼요").
- 마지막 변경 시각·관리자 표시. 변경 이력 화면에 `APP_THEME_UPDATE`가 보인다.
- 테마·마스코트 데이터는 `mobile/src/data/themes.ts`, `mobile/src/data/mascots/`를 별칭으로 가져온다(garmentShapes와 같은 방식). 마스코트 PNG는 별칭 `@app-mascot-images` → `mobile/assets/mascots/` 폴더(vite `server.fs.allow`, `admin/Dockerfile`, 루트 `.dockerignore`에 함께 추가).
