# 07. 관리자 사이트와 AI 공급자 관리

> 백엔드(`backend/`)와 관리자 사이트(`admin/`)가 함께 따르는 계약이다. 코드 관리는 [06_코드_관리.md](06_코드_관리.md)를 따른다.

## 1. 범위

| 포함 | 제외 (다음 단계) |
|---|---|
| 관리자 역할과 관리자 로그인 | 관리자 2단계 인증, IP 제한 |
| 코드 관리 (06 문서의 7개 그룹 추가·수정·비활성·순서·속성) | 상황·분위기 등 추천 로직 값 관리 |
| AI 공급자 관리: Claude 외 OpenAI·Gemini를 추가하고, 모델·우선순위·사용 여부를 관리자 화면에서 바꾼다 | 관리자 2단계 인증, KMS 연동 (출시 전 필수) |
| AI 공급자 시험 분석 (같은 사진으로 공급자별 결과 비교) | 공급자별 비용 단가 관리 |
| AI 분석 기록·통계, 회원 목록·정지, 대시보드, 변경 이력 | 공지·푸시 발송, 리포트 |

## 2. 관리자 역할

- `tb_user.role VARCHAR(20) NOT NULL DEFAULT 'USER'` (`USER`·`ADMIN`). Access 토큰에 `role` 클레임을 넣는다.
- `UserDto`에 `role`을 추가한다. 앱은 무시해도 된다.
- 관리자 계정 만들기: 서버 시작 시 `WEARLY_ADMIN_EMAIL`·`WEARLY_ADMIN_PASSWORD`가 있으면 그 계정을 만들거나 기존 계정을 `ADMIN`으로 올린다(이름은 `WEARLY_ADMIN_NAME`, 기본 "관리자"). 가입 API로는 관리자를 만들 수 없다.
- 관리자 로그인은 일반 `/auth/login`을 쓰고, 관리자 사이트가 응답의 `user.role`이 `ADMIN`인지 확인한다.
- `/api/v1/admin/**`는 `ADMIN`만. 아니면 403 `FORBIDDEN`.
- 회원 상태 `SUSPENDED`: 로그인 403 `ACCOUNT_SUSPENDED`, 기존 토큰 401 `TOKEN_INVALID`, refresh 401 `REFRESH_INVALID`. 7차: 정지하면 그 회원의 로그인 세션을 모두 끊으므로(16 문서) 정지를 풀어도 예전 토큰은 살아나지 않는다(다시 로그인).
- CORS에 관리자 사이트 개발 주소 `http://localhost:5173`을 추가한다.

## 3. AI 공급자

### 테이블 (`tb_ai_provider`)

| 컬럼 | 설명 |
|---|---|
| `provider_id` VARCHAR(30) PK | 관리자가 정하는 이름. 예: `claude`, `openai`, `gemini` |
| `type` VARCHAR(20) | 구현 종류: `CLAUDE`·`OPENAI`·`GEMINI`·`MOCK` |
| `display_name` VARCHAR(50) | 화면 이름 |
| `model` VARCHAR(100) | 모델 ID. 관리자가 화면의 모델 드롭다운에서 고르거나 직접 입력(4장 "모델 목록"). 사용(`enabled`)하려면 필수 |
| `api_key_env` VARCHAR(100) | 키가 들어 있는 환경변수 이름 (예: `ANTHROPIC_API_KEY`). 웹에서 넣은 키가 없을 때 쓴다 (6장) |
| `enabled` BOOLEAN | 사용 여부 |
| `priority` INT | 작을수록 먼저 쓴다 |
| `options` JSONB | 공급자별 설정 (예: Claude `effort`, OpenAI·Gemini `temperature`, `maxTokens`, `baseUrl`) |
| `created_at`·`updated_at` | |

초기값: `claude`(CLAUDE, `claude-opus-5-5`, `ANTHROPIC_API_KEY`, 사용, 1), `openai`(OPENAI, 모델 비움, `OPENAI_API_KEY`, 미사용, 2), `gemini`(GEMINI, 모델 비움, `GEMINI_API_KEY`, 미사용, 3). `MOCK` 행은 두지 않는다.

### 분석 때 공급자 고르기

1. 서버를 목업으로 띄웠으면(`WEARLY_AI_PROVIDER=mock`, `bootRunMock`) 언제나 목업이다. DB 설정은 무시한다.
2. 그 밖에는 `enabled`이고 모델이 있고 키 환경변수에 값이 있는 공급자를 `priority` 순으로 시도한다.
3. 앞 공급자가 실패하면(시간 초과, 5xx, 응답 검증 실패) 다음 공급자로 넘어간다. 실패도 각각 `tb_ai_analysis_log`에 남긴다. 성공한 호출만 일일 한도에 센다.
4. 쓸 수 있는 공급자가 하나도 없으면 502 `AI_UNAVAILABLE`. **목업으로 대신하지 않는다.**
5. 서버 시작 시: 목업 실행이 아닌데 쓸 수 있는 공급자가 하나도 없으면 시작 로그에 WARN을 남긴다(시작은 한다. 관리자가 화면에서 고칠 수 있게). 쓸 수 있는 공급자 목록을 INFO로 남긴다.

- 구현: `CLAUDE`는 기존 Anthropic Java SDK. `OPENAI`·`GEMINI`는 각 사 공식 REST API를 Spring `RestClient`로 호출한다(이미지 + JSON 스키마 구조화 출력). 세 구현 모두 06 문서의 활성 코드로 허용 값 목록·스키마를 만들고 같은 검증을 거친다.
- 모델 칸은 드롭다운이다. 저장된 키가 있으면 제공사에서 모델 목록을 받아 보여 주고, 키가 없거나 받지 못하면 서버 설정의 내장 목록을 보여 준다(4장 "모델 목록"). 목록에 없는 ID도 직접 입력해 저장할 수 있다. 서버가 검증하는 것은 형식뿐이다: 앞뒤 공백을 지운 뒤 `^[A-Za-z0-9._:/@-]{1,100}$`.
- 키 값은 어떤 API 응답·로그에도 내보내지 않는다. 관리자 화면에는 `keyConfigured`, 키 출처, 웹 키의 끝 4자리만 준다(6장).
- 응답 `AnalyzeResponse.provider`는 이제 `provider_id` 문자열(예: `"claude"`, `"openai"`, `"mock"`)이다. 앱은 `"mock"`이면 목업 배지, 그 밖이면 "AI 제안"을 보여 준다.
- `tb_ai_analysis_log.provider`의 CHECK 제약을 지우고 `provider_id`를 그대로 저장한다.

## 4. 관리자 API (`/api/v1/admin`, ADMIN 전용)

목록 응답은 `{ items, page, size, total }`, 쿼리 `page`(0부터)·`size`(기본 20, 최대 100).

### 대시보드

`GET /admin/dashboard` → `{ users, newUsers7d, items, aiToday: { total, success, failed }, aiByProvider7d: [{ providerId, success, failed, avgLatencyMs, inputTokens, outputTokens }], activeSessions, activeUsers24h }` (7차: `activeSessions` = 살아 있는 로그인 세션 수, `activeUsers24h` = 24시간 안에 활동한 회원 수, 16 문서 4장)

### 코드

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/admin/codes` | 06 문서의 `/codes`와 같은 모양 + 그룹 `description`, 코드별 `usageCount`(그 코드를 쓰는 아이템 수) |
| POST | `/admin/codes/{group}` | `{ code, label, parent?, sortOrder?, active?, attrs }` → 201. 코드는 영문 대문자·숫자·밑줄(COLOR는 영문 소문자) 1~30자 |
| PATCH | `/admin/codes/{group}/{code}` | `{ label?, parent?, sortOrder?, active?, attrs? }`. 코드 문자열은 못 바꾼다 |
| PUT | `/admin/codes/{group}/order` | `{ codes: ["TOP", "BOTTOM", ...] }` 순서대로 sortOrder를 10, 20, …으로 |
| DELETE | `/admin/codes/{group}/{code}` | 쓰는 아이템·프로필이 없을 때만. 있으면 409 `CODE_IN_USE` (대신 비활성화) |

- attrs 검증(06 문서 3장): CATEGORY `slot`은 정해진 값 또는 null, SUB_TYPE은 `parent` 필수·`volume` -1~1 정수·`warmth` 0~3 정수·`shape` 1~30자, COLOR는 `hex` `#RRGGBB`·`neutral` bool·`light` 0~1·`pairs`는 있는 COLOR 코드(저장하면 상대 색의 pairs에도 양방향으로 반영), ITEM_STATUS `recommendable` bool. 틀리면 400 `VALIDATION_FAILED` + fieldErrors(`attrs.hex` 형식).
- 같은 코드 중복 409 `CODE_EXISTS`. CATEGORY를 비활성화하면 그 하위 SUB_TYPE도 새로 고를 수 없게 된다(하위 행은 그대로).
- 바꾸면 코드 캐시를 다시 읽고(`/codes`의 version이 바뀜) 변경 이력을 남긴다.

### AI 공급자

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/admin/ai/providers` | `[{ providerId, type, displayName, model, apiKeyEnv, keyConfigured, enabled, priority, options, usable, today: { success, failed } }]` (`usable` = 사용·모델·키 모두 갖춤) |
| POST | `/admin/ai/providers` | `{ providerId, type, displayName, model?, apiKeyEnv, enabled?, priority?, options? }` → 201. `type`은 `CLAUDE`·`OPENAI`·`GEMINI` |
| PATCH | `/admin/ai/providers/{providerId}` | 일부 필드 수정. `enabled: true`로 바꾸려면 모델이 있어야 한다 |
| DELETE | `/admin/ai/providers/{providerId}` | 행 삭제 (분석 기록은 남는다) |
| POST | `/admin/ai/providers/{providerId}/test` | multipart `image` → `{ ok, suggestion?, errorCode?, errorMessage?, latencyMs, inputTokens?, outputTokens?, model }`. 사용 여부와 관계없이 그 공급자로 한 번 호출. 일일 한도에 안 세고, 기록은 `feature='ADMIN_TEST'`로 남긴다 |
| GET | `/admin/ai/providers/{providerId}/models` | 쿼리 `refresh=true\|false`(기본 false). 모델 드롭다운 목록 → 아래 "모델 목록" |
| GET | `/admin/ai/types` | 지원하는 `type` 목록과 각 `options` 설명 (화면 폼용). 각 종류에 내장 모델 `models: [{ id, displayName, recommended }]`(추천 먼저)도 준다. 아직 저장하지 않았거나 종류를 바꾼 공급자의 드롭다운용이다. 내장 목록이 없는 `OPENAI`·`GEMINI`는 `[]` |

#### 모델 목록 (`GET /admin/ai/providers/{providerId}/models`)

응답 `{ source, fetchedAt, models, error }`.

| 필드 | 설명 |
|---|---|
| `source` | `LIVE`(제공사에서 받은 목록) · `CATALOG`(서버 설정의 내장 목록) |
| `fetchedAt` | LIVE는 제공사에서 받은 시각(캐시에서 줘도 처음 받은 시각), CATALOG는 응답을 만든 시각. ISO-8601 |
| `models` | `[{ id, displayName, createdAt, recommended }]`. `createdAt`은 Claude `created_at`, OpenAI `created`(유닉스 초)를 시각으로 바꾼 값이고, Gemini와 내장 목록은 `null` |
| `error` | 정상이면 `null`. CATALOG인 이유면 `{ code, message }` |

- 오류: 일반 회원 403 `FORBIDDEN`, 토큰 없음 401, 없는 공급자 404 `NOT_FOUND`. 제공사 호출이 실패해도 **200 + `CATALOG`** 로 내장 목록과 `error`를 준다.
- `error.code`: `NO_API_KEY`(키가 없어 제공사를 부르지 않음), `MODEL_LIST_FAILED`(제공사 호출 실패). 문구는 401·403이면 "제공사가 API 키를 받아들이지 않았어요 (HTTP 401).", 그 밖의 HTTP 상태, 시간 초과, 연결 실패, 응답 형식 오류마다 따로 있다. 문구와 로그에는 키 값도 제공사 응답 원문도 넣지 않는다.
- 읽기라 변경 이력(감사 로그)을 남기지 않는다. 서비스는 트랜잭션 없이 처리한다(제공사 HTTP 호출 동안 DB 연결을 잡지 않는다).
- 키는 기존 순서(웹 키 → 서버 설정 키)로 고른다. 제공사 호출은 공급자 `options`의 `timeoutSeconds`를 따르고, `baseUrl`은 `WEARLY_AI_ALLOW_BASE_URL=true`일 때만 따른다.
- 제공사 호출
  - Claude: Anthropic SDK `models().list(limit=100).autoPager()`, 최대 500개, `lifecycle=retired`(종료된 모델)는 뺀다.
  - OpenAI: `GET {baseUrl}/models`, `Authorization: Bearer`.
  - Gemini: `GET {baseUrl}/v1beta/models?pageSize=1000`, 키는 `x-goog-api-key` 헤더로만 보낸다. `nextPageToken`을 따라 최대 5쪽.
- 거르기(`ModelListRules`): 사진 분석에 쓸 수 있는 채팅 모델만 남긴다.
  - OpenAI: ID가 `gpt-`로 시작하거나 `o`+숫자로 시작해야 한다. `gpt-3.5*`, `gpt-4`, `gpt-4-0xxx`(이미지 입력이 안 되는 옛 모델)는 뺀다. `embedding`·`tts`·`whisper`·`dall-e`·`moderation`·`realtime`·`audio`·`transcribe`·`search`·`image`·`instruct`·`computer-use`·`deep-research`가 들어 있으면 뺀다.
  - Gemini: `supportedGenerationMethods`에 `generateContent`가 있어야 한다. `models/` 접두사는 뗀다. `embedding`·`aqa`·`imagen`·`veo`·`tts`·`audio`·`image`·`gemma`·`robotics`가 들어 있으면 뺀다.
- 추천·정렬: 내장 목록에 있는 ID는 LIVE에서도 `recommended`다. 제공사가 준 이름이 ID와 같으면 내장 목록의 이름을 쓴다. 같은 ID가 겹치면 처음 것만 남긴다. 정렬은 `recommended` → `createdAt` 최신 → ID.
- 캐시(`AiModelListService`, 서버 메모리): 공급자마다 10분. "종류|`baseUrl`|키 지문"이 같을 때만 쓴다(지문은 SHA-256 앞 16자, `ApiKeyRules.fingerprint`. 키 값은 들고 있지 않는다). `refresh=true`면 캐시를 무시하고 다시 받는다. 웹 키 저장·삭제, 공급자 수정·삭제 때 비운다. 실패는 캐시하지 않고, 실패하면 예전에 받은 목록도 버린다.
- 내장 목록은 `application.yml`의 `wearly.ai.model-catalog.<CLAUDE|OPENAI|GEMINI>: [{ id, display-name, recommended }]`이다. 지금은 `CLAUDE`에 `claude-opus-5-5`, `claude-sonnet-5-5`(추천), `claude-haiku-5-5`. 종류 이름은 대소문자를 가리지 않는다. 모르는 종류나 형식이 틀린 모델 ID면 서버가 시작하지 않는다. 같은 ID는 처음 것만 쓰고, `display-name`이 비면 ID를 쓴다.

### AI 분석 기록

`GET /admin/ai/logs?providerId=&status=&userEmail=&from=&to=` → 기록 행(시각, 회원 이메일, 기능, 공급자, 모델, 상태, 지연, 토큰, 이미지 크기, 결과 요약, 오류 코드). `GET /admin/ai/logs/{id}`는 결과 JSON 전체.

### 회원

- `GET /admin/users?q=&status=&role=` → `[{ id, email, name, role, status, createdAt, itemCount, retiredItemCount, aiToday }]` (6차: `itemCount`는 사용 중인 옷, `retiredItemCount`는 사용 중지한 옷 — 13 문서 3장)
- `PATCH /admin/users/{id}` → `{ status?, role? }`. 자기 자신의 역할은 못 내린다(400). 정지하면 그 회원의 로그인 세션을 모두 끊는다(7차).

### 로그인 세션 (7차, 계약 16 문서 4장)

- `GET /admin/sessions?q=&client=&page=&size=` → `{ items, page, size, total }`, 항목 `{ sessionId, userId, email, name, role, client, userAgent, ip, createdAt, lastRefreshAt, lastSeenAt, current }`. lastSeenAt 최신순, `q`는 이메일·이름 부분 일치, `client`는 `APP`·`ADMIN`·`WEB`(그 밖 400). `current`는 요청한 관리자 자신의 세션.
- `GET /admin/users/{id}/sessions` → `{ sessions: [...같은 항목], events: [{ type, sessionId, client, ip, userAgent, createdAt }] }` (이력은 최근 20개, `type`은 `LOGIN`·`LOGOUT`·`REFRESH_REUSED`·`FORCED_LOGOUT`). 없는 회원 404.
- `DELETE /admin/sessions/{sessionId}` → 204. 그 세션의 Access 토큰은 다음 요청부터 401 `TOKEN_INVALID`, Refresh는 401 `REFRESH_INVALID`. 자기 현재 세션 400(`sessionId`), 없는 세션 404. 이력 `SESSION_REVOKE`.
- `DELETE /admin/users/{id}/sessions` → 204. 그 회원의 모든 세션. 자기 자신 400(`id`), 없는 회원 404. 이력 `USER_SESSIONS_REVOKE`.

### 변경 이력

`tb_admin_audit_log(audit_id, admin_user_id, action, target_type, target_id, before JSONB, after JSONB, created_at)`. 코드·AI 공급자·회원·앱 설정 변경을 남긴다. `GET /admin/audit-logs?targetType=` 목록 (`targetType`은 `CODE`·`AI_PROVIDER`·`USER`·`APP_SETTING`·`SESSION`). 6차: 테마 변경은 `APP_THEME_UPDATE`(`APP_SETTING`/`theme`, 12 문서 3장). 7차: 세션 하나 끊기 `SESSION_REVOKE`(`SESSION`/세션 ID, before `{ userId, email, client, ip, createdAt, lastSeenAt }`), 회원 전체 끊기 `USER_SESSIONS_REVOKE`(`USER`/회원 ID, before `{ email, sessionCount }`, after `{ sessionCount: 0 }`).

## 5. 관리자 사이트 (`admin/`)

- React + Vite + TypeScript, 개발 서버 `http://localhost:5173`. API 주소는 `VITE_API_URL`(기본 `http://localhost:8080`).
- 로그인 → `role`이 `ADMIN`이 아니면 들어갈 수 없다. Access·Refresh 토큰은 `sessionStorage`, 만료 시 자동 갱신. 7차: 모든 요청에 `X-Wearly-Client: admin`(CORS 허용 헤더).
- 화면:
  1. **대시보드**: 회원 수, 아이템 수, 오늘 AI 호출·실패, 공급자별 7일 통계.
  2. **코드 관리**: 그룹 탭, 표(코드·라벨·상위·순서·사용 여부·사용 수), 추가·수정 패널. 그룹별 속성 폼(색은 색 칩 미리보기·어울리는 색 다중 선택, 세부 종류는 상위 종류·보온·볼륨·모양 선택과 **옷 일러스트 미리보기**), 끌어서 순서 바꾸기 또는 위·아래 버튼, 비활성화·삭제(사용 중이면 안내).
  3. **AI 공급자**: 목록(키 설정 여부, 사용 가능 여부, 오늘 호출), 추가·수정(종류·모델·키 환경변수 이름·우선순위·옵션), 사용 켜기/끄기, **시험 분석**: 사진 하나를 올려 공급자 여러 개를 동시에 돌려 결과·지연·토큰을 나란히 비교.
     - **모델 칸은 검색 가능한 드롭다운**(`pages/providers/ModelPicker.tsx`, 순수 함수는 `lib/modelPicker.ts`). 항목은 화면 이름 + 작은 ID + "추천" 배지. 키보드 ↑↓ · Enter · Esc. 맨 아래 "직접 입력…"을 고르면 입력칸으로 바뀌고 "목록에서 고르기"로 돌아온다.
     - 지금 값이 목록에 없으면 처음부터 직접 입력 상태로 값을 그대로 보여 주고 "목록에 없는 모델" 배지와 "새 모델·프리뷰면 그대로 저장할 수 있어요" 안내를 띄운다. 목록이 비어 있으면 직접 입력만 된다.
     - 목록 위에 출처를 적는다. LIVE는 "제공사에서 받은 목록 · 3분 전"과 **새로 받기**(`refresh=true`), CATALOG는 "내장 목록(키가 없거나 목록을 받지 못했어요: <서버 문구>)", 아직 저장하지 않은 공급자는 "내장 목록(저장한 뒤 키가 있으면 제공사 목록을 받을 수 있어요)"(이때 목록은 `/admin/ai/types`의 `models`).
     - 키를 저장·삭제하거나 공급자를 저장하면 모델 목록 쿼리를 무효화해 다시 받는다.
     - 서버가 모델 목록 API에 404를 주거나 `types`에 `models`가 없으면(옛 서버) 예전처럼 텍스트 입력칸을 쓴다.
  4. **AI 분석 기록**: 필터·표·상세(결과 JSON).
  5. **회원**: 검색, 정지·해제, 관리자 지정.

## 6. API 키 웹 입력 (쓰기 전용 · 암호화 저장)

2026-10-17 결정. 관리자 화면에서 공급자 키를 넣고 바꾼다. 키는 **쓰기 전용**이라 넣은 뒤 다시 볼 수 없다.

### 저장

- 테이블 `tb_ai_provider_secret`: `provider_id`(PK, `tb_ai_provider` FK, 공급자 삭제 시 함께 삭제), `ciphertext BYTEA`, `nonce BYTEA`(12바이트), `key_version SMALLINT`, `last4 VARCHAR(4)`, `updated_by`(관리자 user_id, 탈퇴 시 NULL), `updated_at`.
- 암호화: **AES-256-GCM**, 공급자마다 새 무작위 nonce, AAD에 `provider_id`를 넣어 다른 공급자 행에 붙여 넣어도 복호화되지 않게 한다.
- 마스터 키: 환경변수 `WEARLY_SECRET_KEY`(base64로 인코딩한 32바이트). DB에 저장하지 않는다. `key_version`은 지금 1. 나중에 KMS·키 교체를 위해 둔다.
- `WEARLY_SECRET_KEY`가 없으면 웹 키 저장·사용이 꺼진다(저장 API는 409 `SECRET_KEY_MISSING`). 환경변수 키는 그대로 쓴다. 시작 로그에 WARN.
- 복호화한 키는 메모리 캐시에 두고, 키를 바꾸거나 지우면 캐시를 비운다.
- 키를 저장·삭제하면 그 공급자의 모델 목록 캐시(4장 "모델 목록")도 함께 비운다.

### 키 고르기

1. 웹에서 넣은 키(DB)가 있고 복호화되면 그것을 쓴다.
2. 없으면 `api_key_env` 환경변수.
3. 둘 다 없으면 그 공급자는 쓸 수 없다(`usable: false`).

복호화가 실패하면(마스터 키가 바뀜 등) 그 공급자를 쓸 수 없는 것으로 보고 ERROR 로그를 남긴다. 키 값은 로그에 남기지 않는다.

### API (ADMIN 전용)

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| PUT | `/admin/ai/providers/{providerId}/api-key` | `{ apiKey, currentPassword, verify? }` (`verify` 기본 true) | 200 공급자 행 |
| DELETE | `/admin/ai/providers/{providerId}/api-key` | `{ currentPassword }` | 200 공급자 행 (환경변수 키로 되돌아감) |

- `currentPassword`: 요청한 관리자의 비밀번호를 다시 확인한다. 틀리면 403 `REAUTH_FAILED`.
- `apiKey`: 앞뒤 공백을 지운 뒤 20~300자, 공백·줄바꿈 없음. 틀리면 400 `VALIDATION_FAILED`(`apiKey`).
- `verify: true`면 저장 전에 그 키로 **모델 목록 조회**를 한 번 해서 유효한지 본다(사진 분석보다 싸다). Claude `GET /v1/models`, OpenAI `GET /v1/models`, Gemini `GET /v1beta/models`. 실패하면 저장하지 않고 400 `API_KEY_INVALID`(공급자 오류 메시지는 키 조각을 지우고 붙인다). 각 사 엔드포인트는 공식 명세로 확인한다.
- 변경 이력: `AI_PROVIDER_KEY_SET`·`AI_PROVIDER_KEY_DELETE`. before·after에는 `keySource`·`keyLast4`만 남긴다.

### 공급자 행에 더하는 필드

```ts
{
  keySource: 'DB' | 'ENV' | 'NONE';   // 지금 실제로 쓰는 키의 출처
  keyLast4: string | null;            // DB 키일 때만
  keyUpdatedAt: string | null;        // DB 키일 때만
  keyUpdatedBy: string | null;        // DB 키를 넣은 관리자 이메일
  secretStoreEnabled: boolean;        // WEARLY_SECRET_KEY가 있어 웹 키를 쓸 수 있는지
}
```

`keyConfigured`는 `keySource !== 'NONE'`과 같다.

### 관리자 사이트

- 공급자 상세에 "API 키" 영역: 출처(웹 입력 `••••abcd` · 날짜 · 넣은 관리자 / 환경변수 `ANTHROPIC_API_KEY` / 없음).
- "키 입력·교체": 키 입력칸(비밀번호 형식, 붙여넣기 허용, 화면에 다시 보여 주지 않음) + 내 비밀번호 + "저장 전 유효성 확인" 체크(기본 켬). 저장 뒤 입력칸을 바로 비운다.
- "웹 키 삭제(환경변수로 되돌리기)": 비밀번호 확인 후.
- `secretStoreEnabled`가 false면 입력 버튼을 막고 "서버에 WEARLY_SECRET_KEY가 없어 웹 입력을 쓸 수 없어요" 안내.
- 키는 브라우저 저장소·로그·쿼리 문자열에 남기지 않는다.
