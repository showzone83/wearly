# 24. 쇼핑몰 캡처로 옷 사진 등록

> 2026-10-20. 옷 사진을 카메라·앨범 말고 **쇼핑몰 화면 캡처**로도 등록한다. 관리자가 등록한 쇼핑몰을 앱 안 웹 화면으로 열고, 상품 사진을 정사각 틀에 맞춰 캡처하면 그 사진이 옷 사진이 된다. 사진을 받은 뒤의 올리기·AI 분석·저장은 카메라·앨범과 같다([18 문서](18_사진_저장.md) 9장).

## 1. 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 쇼핑몰 목록 | 코드 그룹 `MALL`, `attrs.url` | 관리자 코드 관리(추가·수정·순서·끄기·변경 이력)와 앱의 `GET /codes`(ETag 캐시)를 그대로 쓴다. 쇼핑몰별 데이터가 주소 하나뿐이라 전용 테이블은 과하다 |
| 캡처 범위 | **정사각 틀 안만**. 틀 크기·위치는 사용자가 바꾼다(정사각 유지) | 카메라·앨범의 1:1 자르기와 같은 모양이라 AI 분석·목록 썸네일이 그대로 맞는다. 쇼핑몰 메뉴·글자가 사진에 들어가지 않는다. 상품 사진 크기·위치가 쇼핑몰마다 달라 틀을 맞출 수 있어야 한다(실기기 확인 뒤 추가) |
| 넣는 곳 | 옷 등록 1단계 + 옷 상세 사진 시트 | 새 옷 등록과 사진 바꾸기 둘 다 |
| 패키지 | `react-native-webview` 14.0.1, `react-native-view-shot` 6.1.1 (`npx expo install`, SDK 58. SDK 57 때는 13.16.1·5.1.0) | 둘 다 Expo SDK 57·58 문서에 **Expo Go 포함**이라 개발 빌드 없이 확인할 수 있다 |
| 웹 체험판 | 버튼·시트 선택지를 숨긴다 | `react-native-webview`가 웹을 지원하지 않는다 |
| 서버 사진 처리 | 바꾸지 않음 | 캡처는 PNG이고 기존 업로드(`purpose: ITEM`, JPEG·PNG)가 받는다. `complete`가 JPEG 1600·썸네일 400으로 다시 저장하고 메타데이터를 지운다 |
| 사진 출처 기록 | 하지 않음 | 지금은 쓰는 곳이 없다. 필요해지면 `tb_item_image`에 칸을 더한다 |

## 2. 코드 그룹 `MALL` (`V25__mall_codes.sql`)

- 그룹: `MALL` "쇼핑몰", `sort_order` 130 (FIT 다음, [06 문서](06_코드_관리.md) 3장)
- 코드: 대문자·숫자·밑줄 1~30자, 이름 50자 이하 (코드 공통 규칙)
- `attrs.url`: 앱이 처음 여는 주소. **필수, `https://`만, 호스트 있음, 사용자 정보(`user@`) 없음, 500자 이하**. 모르는 attrs 키는 거부한다.
  - 서버 `CodeAttrs.isHttpsUrl`과 관리자 폼 `isHttpsUrl`, 앱 `mallCaptureRules.isHttpsUrl`이 같은 규칙이다.
  - 오류는 기존 필드 코드를 쓴다: `REQUIRED`, `INVALID_TYPE(expected: string)`, `INVALID_FORMAT(format: url)`, `TOO_LONG(max: 500)`. 새 오류 코드는 없다.
- 초기값(운영에서 관리자가 바꾼다):

| 코드 | 이름 | url | 순서 |
|---|---|---|---|
| `MUSINSA` | 무신사 | `https://www.musinsa.com` | 10 |
| `29CM` | 29CM | `https://www.29cm.co.kr` | 20 |
| `WCONCEPT` | W컨셉 | `https://www.wconcept.co.kr` | 30 |
| `ZIGZAG` | 지그재그 | `https://zigzag.kr` | 40 |
| `ABLY` | 에이블리 | `https://m.a-bly.com` | 50 |

- 앱에는 **활성이고 `attrs.url`이 https인 코드만** 순서대로 보인다. 앱 안에서 잘 열리지 않는 쇼핑몰은 관리자가 비활성으로 둔다.
- 쓰는 아이템이 없어 `CODE_IN_USE`로 막히지 않는다. 지워도 이미 등록한 옷 사진에는 영향이 없다.
- 관리자 코드 폼: MALL 탭에 "처음 열 주소 (url)" 입력칸(https 검사), 목록에는 주소의 호스트를 링크로 보인다 ([07 문서](07_관리자_사이트.md) 5장).

## 3. 앱 흐름

```
옷 등록 1단계 "쇼핑몰에서 가져오기"  ─┐
옷 상세 사진 시트 "쇼핑몰에서 가져오기" ─┴─▶ item/mall?for=<new | 옷 ID>
   ① 쇼핑몰 목록 (코드 MALL)
   ② 고른 쇼핑몰을 WebView로 연다 (머리: 뒤로·이름·닫기)
   ③ 상품 사진을 정사각 틀에 맞추고(모서리로 크기·가운데로 위치) [캡처]
   ④ captureRef(PNG) → 틀 위치만 자르기(ImageManipulator.crop) → useMallCapture에 넣고 닫기
부른 화면이 자기 몫(for)을 꺼낸다
   옷 등록: analyze({ uri, width, height })  → 올리기 → AI 분석 → 3단계 확인·수정
   옷 상세: runReplace({ uri, width, height }) → 사진 바꾸기 → AI 다시 분석 제안
```

| 파일 | 내용 |
|---|---|
| `mobile/src/app/item/mall.tsx` | 쇼핑몰 목록 → 웹 화면 → 캡처. `_layout.tsx`에 `fullScreenModal`로 등록 (옷 등록 모달 위에도 뜬다) |
| `mobile/src/lib/mallCaptureRules.ts` | 순수 규칙: `mallList`·`isHttpsUrl`·`isAllowedNavigation`·`frameRect`·`resizeFrame`·`moveFrame`·`clampFrame`·`cropRect`, 안내 문구. `tests/mallCapture.test.mjs` |
| `mobile/src/lib/mallCapture.ts` | `availableMalls()`(웹이면 빈 목록), `openMallCapture(target)` |
| `mobile/src/store/useMallCapture.ts` | 캡처 결과를 부른 화면에 넘기는 작은 스토어 (`put` · `take(target)`, 기기에 저장 안 함) |
| `mobile/src/lib/photoEditRules.ts` | 사진 시트 선택지 `mall` ("쇼핑몰에서 가져오기", 사진 빼기 앞, 쓸 수 있을 때만) |

### 3.1 이동 제한

`onShouldStartLoadWithRequest`에서 웹 주소(`http`·`https`)와 페이지가 안에서 쓰는 `about`·`data`·`blob`만 연다. `intent:`·`market:`·쇼핑몰 앱 스킴·`kakaotalk:`·`tel:`·`mailto:`·`javascript:`처럼 다른 앱을 여는 주소는 막는다(쇼핑몰 앱 설치 유도 등). 새 창은 열지 않는다(`setSupportMultipleWindows={false}`). 웹 화면에서 뒤로 갈 곳이 있으면 머리의 뒤로가 웹 뒤로, 없으면 쇼핑몰 목록으로 간다.

### 3.2 캡처·자르기

- 처음 틀: 웹 화면 영역 가운데 정사각. 한 변 = 짧은 변 − 양쪽 여백 24(논리 px). 틀 밖은 어둡게 덮는다.
- 틀 바꾸기 (정사각 유지, RN 기본 `PanResponder`라 새 패키지 없음)
  - **모서리 손잡이 4개**(흰 꺾쇠, 터치 영역 44): 끌면 마주 보는 모서리를 고정하고 크기가 바뀐다. 늘어나는 양은 모서리 바깥 방향으로 맞춘 dx·dy의 평균(`resizeFrame`).
  - **가운데 손잡이**(원): 끌면 크기는 그대로 위치만 바뀐다(`moveFrame`).
  - 한 변은 최소 120(`MIN_FRAME_SIDE`), 틀은 화면 밖으로 나가지 않는다. 화면 크기가 바뀌면 `clampFrame`으로 화면 안에 넣는다.
  - 다른 쇼핑몰을 열면 처음 틀로 돌아간다.
  - 손잡이를 끄는 동안에는 웹 화면이 터치를 가져가지 않는다(`onPanResponderTerminationRequest: false`).
- 틀·덮개·손잡이는 **캡처하는 뷰(`shotRef`) 밖의 형제 요소**라서 사진에 찍히지 않는다. 덮개·테두리는 `pointerEvents="none"`이라 손잡이 밖(틀 안 포함)의 스크롤·확대는 웹 화면으로 그대로 간다.
- 틀을 작게 줄이면 사진도 작아진다. 긴 변 600 미만이면 옷 등록·상세의 기존 "흐리게 보일 수 있어요" 안내가 뜬다.
- 캡처 이미지는 기기 배율(PixelRatio)만큼 크다. `cropRect`가 가로·세로 배율을 따로 곱해 틀 위치를 이미지 픽셀로 바꾸고, 이미지 밖으로 나가지 않게 자른다.
- 결과는 캐시 폴더의 PNG다. 올릴 때 기존 `preparePhoto`가 긴 변 1600 JPEG(0.8)로 바꾼다. 사진이 작으면(긴 변 600 미만) 기존 "흐리게 보일 수 있어요" 안내가 그대로 뜬다.

### 3.3 저작권 안내

쇼핑몰 상품 사진은 쇼핑몰·브랜드의 저작물이다. 캡처한 사진은 회원 본인의 옷장 기록(비공개 버킷, 서명 URL)에만 쓰고 다른 회원에게 보이지 않는다. 단, **옷장 도우미**([26](26_옷장_도우미.md))로 연결된 돕는 사람은 주인의 옷 사진을 볼 수 있어 캡처 사진도 보인다 (결정 D6, 주인이 승인한 연결 안에서만). 화면 아래에 "캡처한 사진은 내 옷장 기록용으로만 써 주세요."를 보인다. 앞으로 코디 공유처럼 사진이 다른 사람에게 보이는 기능을 만들 때는 캡처 사진을 어떻게 다룰지 따로 정한다.

## 4. 알려진 한계와 확인할 것

- **Android WebView 캡처**: `react-native-view-shot`으로 Android WebView가 검게 찍히는 경우가 있다고 알려져 있다. 실기기(Expo Go)에서 먼저 확인하고, 검게 나오면 WebView에 `androidLayerType="software"`를 주고 다시 본다.
- 일부 쇼핑몰은 앱 안 웹 화면에서 로그인·결제 창을 막는다. 상품 사진만 보면 되므로 문제로 보지 않고, 상품 화면도 안 열리면 관리자가 코드를 끈다.
- 웹 체험판(브라우저)에서는 쓸 수 없다.
- 앱의 목업 실행(`npm run start:mock`)은 기기 안 코드 초기값(`src/data/codes.seed.json`)의 MALL을 쓴다. 웹 화면은 인터넷이 필요하다.
