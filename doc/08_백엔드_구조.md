# 08. 백엔드 구조: 헥사고날 + JPA + MyBatis

> 대상: `backend/`. 2026-10-17 결정. 그전에는 기능별 패키지 안에 컨트롤러·서비스·JPA 엔티티·리포지토리·MyBatis 매퍼가 섞인 계층형 구조였다.

## 1. 원칙

- **도메인과 유스케이스는 바깥 기술을 모른다.** Spring Web, JPA, MyBatis, Anthropic SDK, HTTP 클라이언트는 모두 어댑터에만 있다.
- **안쪽으로만 의존한다.** `adapter` → `application` → `domain`. 반대 방향 import는 금지하고 ArchUnit 테스트로 막는다.
- **쓰기는 JPA, 읽기는 MyBatis.** 둘 다 출력 어댑터다. 쓰기 포트(저장·단건 로드)는 JPA 어댑터가, 조회 포트(목록·검색·집계)는 MyBatis 어댑터가 구현한다.
- **JPA 엔티티는 도메인 모델이 아니다.** 영속성 어댑터 안에서 JPA 엔티티 ↔ 도메인 모델을 바꾼다. 도메인 모델에는 `@Entity` 같은 어노테이션을 붙이지 않는다.

## 2. 패키지

바운디드 컨텍스트(기능)마다 같은 모양을 쓴다. 컨텍스트: `auth`, `user`, `wardrobe`, `code`, `ai`, `admin`.

```
app.wearly
├── <context>
│   ├── domain/                    도메인 모델·값 객체·도메인 규칙 (순수 자바, Spring·JPA·Jackson 어노테이션 없음)
│   ├── application/
│   │   ├── port/in/               유스케이스 인터페이스 + 명령(Command)·조회 조건 객체
│   │   ├── port/out/              출력 포트 (예: SaveItemPort, LoadItemPort, ItemQueryPort, AiModelPort)
│   │   └── service/               유스케이스 구현 (@Service, @Transactional은 여기까지만)
│   └── adapter/
│       ├── in/web/                @RestController, 요청·응답 DTO, DTO ↔ 명령 변환
│       └── out/
│           ├── persistence/       JPA 엔티티·Spring Data 리포지토리·쓰기 포트 어댑터
│           ├── query/             MyBatis 매퍼 인터페이스·조회 포트 어댑터 (XML은 resources/mapper/<context>/)
│           └── <기술>/             예: ai/claude, ai/openai, ai/gemini, ai/mock, crypto
└── common
    ├── domain/                    여러 컨텍스트가 같이 쓰는 값 객체 (예: UserId)
    ├── error/                     오류 코드·예외·전역 예외 처리(웹 어댑터 쪽)
    ├── config/                    Spring 설정, 보안 설정
    └── mybatis/                   공용 TypeHandler
```

## 3. 규칙

| 대상 | 의존해도 되는 것 | 의존하면 안 되는 것 |
|---|---|---|
| `domain` | 자바 표준, `common.domain` | Spring, JPA, MyBatis, Jackson, 다른 컨텍스트의 `application`·`adapter` |
| `application` | 자기 `domain`, 다른 컨텍스트의 `port.in`(유스케이스 호출), `common.domain`·`common.error`, Spring의 `@Service`·`@Transactional` | 어떤 `adapter`, JPA 엔티티, MyBatis 매퍼, Web 타입(`ResponseEntity`, `MultipartFile` 등) |
| `adapter.in.web` | 자기 `port.in`, 웹 DTO | 출력 포트·출력 어댑터 직접 호출 |
| `adapter.out.*` | 자기 `port.out`, `domain`, 기술 라이브러리 | 유스케이스 서비스, 웹 어댑터 |

- 컨텍스트 사이 호출은 상대 컨텍스트의 **입력 포트(유스케이스)** 로만 한다. 예: `admin`이 코드를 고치면 `code`의 유스케이스를 부른다. 다른 컨텍스트의 리포지토리·매퍼를 직접 쓰지 않는다.
- 이미지 업로드(`MultipartFile`)는 웹 어댑터에서 `byte[]`와 MIME을 담은 도메인 값으로 바꿔 넘긴다.
- 트랜잭션 경계는 `application.service`. JPA와 MyBatis가 한 트랜잭션에 함께 들어가도 같은 DataSource·트랜잭션 매니저를 쓴다.
- 감사 로그(`tb_admin_audit_log`)는 출력 포트(`RecordAuditPort`)로 남긴다.

## 4. 검증

- **ArchUnit 테스트**로 3장 규칙을 강제한다(`domain`·`application`이 어댑터·JPA·MyBatis·Spring Web을 import하지 않음, 컨텍스트 사이 의존은 `port.in`만).
- 구조를 바꾸는 단계에서는 **동작을 바꾸지 않는다.** API 계약(05·06·07 문서), DB 스키마, 기존 테스트 78개, 연동 하네스 29개가 그대로 통과해야 한다.
- 도메인 규칙(코드 검증, 토큰 회전, 공급자 선택 순서 등)은 Spring 없이 도는 단위 테스트를 둔다.
